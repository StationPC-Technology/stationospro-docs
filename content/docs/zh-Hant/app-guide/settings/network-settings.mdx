網路設定頁分為 **一般** 與 **網路連線**。一般頁負責全域閘道、DNS 與進階解析策略；網路連線頁負責每塊網路卡的 IP 參數、橋接和鏈路聚合。

## 一般

![Network General](/images/zh-Hant/app-guide/settings-img/network-general.png)

### 預設閘道

| 欄位 | 說明 |
| --- | --- |
| 預設閘道 | 目前 IPv4 預設閘道，例如 `172.16.0.1`。裝置存取其他網段或網際網路時優先使用。 |
| IPv6 預設閘道 | 目前 IPv6 預設閘道；未設定或不可用時顯示 `-`。 |

### DNS 伺服器

| 選項 | 說明 |
| --- | --- |
| 手動設定 DNS 伺服器 | 未勾選時使用 DHCP 等方式自動取得 DNS；勾選後可手動填寫。 |
| 主要 DNS 伺服器 | 必填。網域名稱解析的首選伺服器，例如 `202.96.134.33`。 |
| 次要 DNS 伺服器 | 選填。主要 DNS 不可用時使用，例如 `202.96.128.86`。 |

### 進階設定

| 選項 | 說明 |
| --- | --- |
| 啟用多閘道 | 允許系統使用多個閘道。適合裝置連接多個網段或多個上行鏈路的情境。 |
| DNS 解析優先使用 IPv4 | 網域名稱同時有 IPv4/IPv6 記錄時優先選擇 IPv4，可避免部分 IPv6 網路不通導致存取緩慢。 |
| 啟用 IP 衝突偵測 | 偵測區域網路內位址衝突，幫助發現靜態 IP 與其他裝置衝突的問題。 |
| 套用 | 點擊後儲存目前頁面修改；未修改時按鈕不可用。 |

<Callout title="注意" type="warn">
  如果目前瀏覽器就是透過網路存取裝置，修改閘道、DNS 或網路卡 IP 後連線可能中斷。請確認新參數可路由，並準備透過新 IP 或主控台恢復連線。
</Callout>

## 網路連線

![Network Connections](/images/zh-Hant/app-guide/settings-img/network-connections.png)

### 網路卡列表

每個網路卡卡片顯示：

| 欄位 | 說明 |
| --- | --- |
| 介面名稱 | 例如 Port 1 (`enP2p33s0`)、Port 2 (`enP4p65s0`)。 |
| 速率 | 目前協商速率，例如 1Gbps。 |
| 雙工模式 | 全雙工或半雙工。 |
| MTU | 目前最大傳輸單元，例如 MTU1500。 |
| 連線狀態 | 已連線、未連線、不可用等。 |
| MAC 位址 | 網路卡硬體位址。 |
| IPv4 位址 / 子網路遮罩 / 閘道 | IPv4 連線參數，位址旁可複製。 |
| DNS | IPv4 DNS 伺服器列表。 |
| IPv6 位址 / 閘道 / DNS | IPv6 連線參數；未設定時顯示 `-`。 |
| 網路類型 | 乙太網路、橋接、鏈路聚合等。 |

### 編輯網路卡

點擊網路卡卡片上的編輯按鈕後可修改：

| 設定 | 模式 | 欄位與規則 |
| --- | --- | --- |
| IPv4 | 自動 | 由 DHCP 自動取得位址、遮罩、閘道與 DNS；手動輸入框停用。 |
| IPv4 | 手動 | 必填 IPv4 位址與子網路遮罩；可填閘道、主要 DNS、次要 DNS。位址必須為有效 IPv4 格式，子網路遮罩必須是連續遮罩。 |
| MTU | 自動 | 使用系統預設 MTU。 |
| MTU | 手動 | 可輸入 1280~9000。修改前請確認交換器與鏈路支援對應訊框大小。 |

### 建立橋接

**Create Bridge** 可將兩塊或以上實體網路卡加入同一個橋接網路：

1. 點擊 **Create Bridge**。
2. 選擇至少兩塊可用實體網路卡。
3. 確認後系統建立橋接介面。
4. 建立後可像一般介面一樣編輯 IP 參數。

<Callout title="提示" type="info">
  橋接常用於讓虛擬機、容器或隔離網路直接接入實體區域網路。建立橋接可能改變原網路卡連線方式，請避免選錯目前管理網路卡。
</Callout>

### 建立鏈路聚合

**Create Link Aggregation** 可將多塊網路卡合併為一個邏輯介面，實現頻寬疊加或鏈路備份。系統要求使用同規格網路卡。

| 分類 | 模式 | 特點與要求 |
| --- | --- | --- |
| 無需交換器設定 | Adaptive Load Balancing – bond6 | 推薦。系統自動在多個網路埠間分配流量，不需要交換器支援聚合。 |
| 無需交換器設定 | Active/Backup – bond1 | 主備模式。備援埠平時不活躍，主埠故障後自動切換，可靠性高但不疊加頻寬。 |
| 需要交換器設定 | Round Robin – bond0 | 輪詢分配流量，兩埠同時傳輸，可顯著提高速度；要求交換器支援並正確設定靜態聚合。 |
| 需要交換器設定 | Balance XOR – bond2 | 基於雜湊分配鏈路；要求交換器支援靜態聚合，多交換器情境需堆疊並正確設定。 |
| 需要交換器設定 | Dynamic Link Aggregation – bond4 | IEEE 802.3ad 動態聚合；要求交換器支援 LACP 並正確設定，多交換器需堆疊。 |

### 解除網路模式

對於橋接或鏈路聚合介面，可透過更多操作解除網路模式。系統會提示該操作影響對應邏輯介面，確認後恢復成員網路卡。

<Callout title="操作建議" type="warn">
  鏈路聚合模式必須與交換器設定相符。若選擇了需要交換器支援的模式但交換器未設定，可能導致網路中斷或聚合埠反覆異常。
</Callout>

## 修改網路前的準備

1. 記錄目前 IP、遮罩、閘道、DNS、MTU 和介面名稱。
2. 確認有區域網路、主控台或第二網路埠恢復路徑。
3. 確認交換器 VLAN、連接埠速率、聚合和防火牆策略。
4. 確認新靜態 IP 不與其他裝置衝突。
5. 若使用鏈路聚合，先在交換器端完成對應設定並核對模式。
6. 不要同時修改多個網路條件；每次修改後先驗證連線。

## 介面狀態解讀

| 狀態/欄位 | 含義 |
| --- | --- |
| Connected | 鏈路已建立並可取得位址。 |
| Disconnected | 網路線/鏈路未建立。 |
| 1Gbps / 2.5Gbps / 10Gbps | 目前協商速率，受兩端裝置和線材限制。 |
| Full Duplex | 可同時收發；半雙工效率較低。 |
| MTU1500 | 標準乙太網路 MTU；Jumbo MTU 需全鏈路支援。 |
| `-` | 未取得值或該協定堆疊未設定。 |
| Bridge | 由多塊實體介面組成的橋接。 |
| Bond | 由多塊網路卡組成的鏈路聚合邏輯介面。 |

## 橋接與鏈路聚合選擇

| 需求 | 選擇 |
| --- | --- |
| 讓虛擬機/容器直接進入實體區域網路 | 橋接。 |
| 兩塊網路卡頻寬疊加，不需要交換器設定 | bond6。 |
| 主備容災，切換優先 | bond1。 |
| 交換器已設定靜態聚合，追求並行吞吐量 | bond0 或 bond2。 |
| 交換器支援 LACP，需要標準動態聚合 | bond4。 |
| 只修改 NAS 的 IP/DNS | 一般介面編輯，不要建立橋接或聚合。 |

## 恢復連線的常用方法

- 使用另一個未修改網路埠的 IP 存取。
- 將電腦接入同 VLAN/同網段後重新掃描裝置。
- 透過路由器 DHCP 租約列表尋找新位址。
- 若僅 DNS 異常，暫時直接存取 IP。
- 若聚合埠失聯，斷開成員埠後使用單埠恢復設定。
- 嚴重網路設定錯誤時，可在更新與還原中評估重設網路。

通知設定頁分為 **電子郵件** 與 **通知語言**。郵件通知服務用於傳送帳號安全郵件，例如雙重驗證緊急驗證碼、密碼重設郵件等；通知語言決定郵件、簡訊等推送內容使用的語言。

## 電子郵件

![Email Notification](/images/zh-Hant/app-guide/settings-img/notifications.png)

### 郵件通知服務

| 功能/欄位 | 說明 |
| --- | --- |
| 服務開關 | 開啟後系統可透過指定 SMTP 服務傳送安全郵件。 |
| 寄件信箱 | 顯示目前寄件信箱；未設定時顯示「未設定」。 |
| 編輯 | 開啟郵件設定彈出視窗，設定服務供應商、寄件信箱和驗證資訊。 |
| 郵件主旨前綴 | 設定系統郵件標題前綴，便於在信箱中識別來源裝置。 |
| 傳送測試郵件 | 向指定收件信箱傳送一封測試郵件，驗證 SMTP 設定是否可用。 |

<Callout title="雙重驗證相依性" type="warn">
  雙重驗證需要郵件通知服務支援。若系統已強制使用雙重驗證，直接關閉郵件服務可能導致登入驗證碼無法傳送；頁面會提示先前往帳號安全設定關閉雙重驗證。
</Callout>

### 郵件設定

#### 預設信箱

選擇 Gmail、QQ 信箱、126 信箱、163 信箱時需要設定：

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| 信箱服務供應商 | 是 | 選擇系統預設服務供應商。 |
| 寄件信箱 | 是 | 用於傳送系統郵件的信箱位址。 |
| 授權碼 | 是 | 在信箱服務供應商中產生的 SMTP 授權碼，通常不是信箱登入密碼。 |

預設信箱通常使用 SSL 465 連接埠。頁面會提醒確保防火牆輸出規則沒有封鎖對應連接埠。

#### 自訂信箱

選擇自訂信箱後需要設定：

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| SMTP 伺服器 | 是 | 郵件服務供應商的 SMTP 位址，例如 `smtp.example.com`。 |
| 連接埠 | 是 | 依 SMTP 服務填寫。常見預設連接埠：無加密 25、SSL 465、TLS 587。 |
| 安全類型 | 是 | 可選無、SSL、TLS。建議使用 SSL 或 TLS。 |
| 使用者名稱 | 是 | SMTP 驗證使用者名稱，通常為信箱帳號。 |
| 密碼 | 是 | SMTP 密碼或授權碼。 |
| 寄件人名稱 | 否 | 顯示在郵件寄件人名稱中。 |
| 寄件信箱 | 是 | 實際對外寄送郵件的信箱位址。 |

### 如何取得信箱授權碼

SMTP 授權碼是信箱服務商為第三方郵件用戶端產生的專用密碼，常見名稱包括 **應用程式密碼**、**App Password**、**應用程式專用密碼**。它通常不是信箱登入密碼；產生後請立即複製，並填入系統的授權碼或密碼欄位。

產生前，請先登入信箱服務商網頁版完成帳號安全驗證，並確認帳號已開啟服務商要求的兩步驟驗證或二次驗證。

| 信箱 | 授權碼/應用程式密碼取得方式 | SMTP 設定參考 |
| --- | --- | --- |
| Gmail | 進入 Google 帳號的「安全性」設定，開啟「兩步驟驗證」後打開「應用程式密碼」，輸入用途名稱並產生。組織帳號需管理員允許使用應用程式密碼。 | 在系統中選擇 Gmail 預設。 |
| QQ 信箱 | 登入網頁版，進入「設定」→「帳號」，開啟 POP3/IMAP/SMTP 服務，並依頁面提示完成安全驗證後產生授權碼。 | 在系統中選擇 QQ 信箱預設。 |
| Outlook.com、Hotmail、Live | 進入 Microsoft 帳號的「安全性」設定，打開「進階安全性選項」，在「應用程式密碼」中建立新的應用程式密碼。 | 自訂信箱：`smtp-mail.office.com`，連接埠 `587`，安全類型 `TLS`。 |
| Microsoft 365 工作或學校信箱 | 由管理員確認信箱已允許 SMTP 寄信，並按組織的多重驗證策略建立應用程式密碼。部分組織會停用應用程式密碼或 SMTP。 | 自訂信箱：`smtp.office365.com`，連接埠 `587`，安全類型 `TLS`。 |
| 163 信箱 | 登入網頁版，進入「設定」→「POP3/SMTP/IMAP」，開啟 SMTP 服務並產生用戶端授權密碼。 | 在系統中選擇 163 信箱預設。 |
| Yahoo Mail | 進入 Yahoo 帳號的「Account Security」，選擇產生應用程式密碼，並記錄產生的密碼。 | 自訂信箱：`smtp.mail.yahoo.com`，連接埠 `465/SSL` 或 `587/TLS`。 |
| iCloud Mail | 進入 Apple 帳號的「登入與安全」，選擇「App 專用密碼」並產生。需要先開啟雙重認證。 | 自訂信箱：`smtp.mail.me.com`，連接埠 `587`，安全類型 `TLS`。 |
| AOL Mail | 進入 AOL 帳號的「Security」設定，選擇產生應用程式密碼。 | 自訂信箱：`smtp.aol.com`，連接埠 `465/SSL` 或 `587/TLS`。 |
| Zoho Mail | 進入 Zoho 帳號的安全設定，選擇「App Passwords」並產生。 | 自訂信箱：`smtp.zoho.com`，連接埠 `465/SSL` 或 `587/TLS`；使用自訂網域或區域帳號時以 Zoho 提供的地址為準。 |
| 126 信箱 | 登入網頁版，進入「設定」→「POP3/SMTP/IMAP」，開啟 SMTP 服務並產生用戶端授權密碼。 | 在系統中選擇 126 信箱預設。 |

<Callout title="服務商策略可能變更" type="info">
  信箱服務商的入口名稱、帳號類型和管理員策略可能變化。若無法產生應用程式密碼，或產生後測試郵件仍失敗，請改用服務商明確允許 SMTP 寄信的信箱，或聯絡信箱管理員確認輸出策略。
</Callout>

### 郵件主旨前綴

| 選項 | 說明 |
| --- | --- |
| 使用裝置名稱 | 自動使用目前裝置名稱作為郵件標題前綴。 |
| 自訂 | 手動輸入前綴；選擇該方式時前綴必填。 |

郵件主旨前綴適合多台裝置共用一個信箱接收通知時快速區分來源裝置。

### 傳送測試郵件

1. 確認郵件服務已設定並開啟。
2. 點擊 **傳送測試郵件**。
3. 輸入收件信箱。
4. 點擊 **傳送**。
5. 到收件匣檢視測試郵件；若未收到，請檢查授權碼、SMTP 連接埠、安全類型和防火牆輸出規則。

## 通知語言

![Notification Language](/images/zh-Hant/app-guide/settings-img/notification-language.png)

| 選項 | 說明 |
| --- | --- |
| 通知語言 | 控制郵件、簡訊等推送內容語言。 |
| 可選語言 | 簡體中文、繁體中文、English、日本語、한국어、Deutsch、Français、Español。 |
| 套用 | 儲存語言修改。 |

<Callout title="提示" type="info">
  通知語言只影響系統推送內容，不會直接切換 Web 桌面介面語言。桌面語言可在個人設定中調整。
</Callout>

## 郵件設定疑難排解

| 現象 | 檢查 |
| --- | --- |
| 授權碼錯誤 | 服務供應商是否開啟 SMTP、授權碼是否複製完整、是否使用登入密碼代替授權碼。 |
| 連線 SMTP 逾時 | SMTP 位址、連接埠、安全類型、防火牆輸出規則。 |
| 使用 SSL 連接埠但選擇 TLS | 核對服務供應商文件；常見 465/SSL、587/TLS。 |
| 郵件進入垃圾郵件 | 寄件人名稱、SPF/DKIM/DMARC、自訂網域名稱 DNS。 |
| 測試郵件成功但驗證碼未收到 | 收件匣垃圾郵件、通知語言、帳號安全策略、郵件延遲。 |
| 關閉郵件服務被阻擋 | 系統偵測到雙重驗證相依郵件，需先關閉相關策略。 |

## 自訂 SMTP 檢查清單

1. SMTP 伺服器位址是否為服務供應商推薦位址。
2. 連接埠與安全類型相符。
3. 使用者名稱是否為完整信箱或服務供應商要求的帳號。
4. 密碼/授權碼不是空格或換行。
5. 寄件信箱與 SMTP 帳號一致，或服務供應商明確允許別名。
6. 防火牆未封鎖對應輸出連接埠。
7. 傳送測試郵件並檢查垃圾郵件資料夾。

## 語言與多裝置通知

- 通知語言作用於系統傳送的郵件或簡訊內容。
- 已傳送的歷史郵件不會因後續修改而重新翻譯。
- 多台裝置使用同一個寄件信箱時，建議設定不同主旨前綴，例如裝置名稱、位置或用途。

Notification Settings contains **Email** and **Notification Language** tabs.

## Email

![Email Notification](/images/common/app-guide/settings-img/notifications.png)

| Feature | Description |
| --- | --- |
| Email notification service | Sends account-security messages such as emergency two-step verification codes and password-reset emails. |
| Sender email | Shows the configured sender or **Not configured**. |
| Edit | Configures provider and SMTP credentials. |
| Email Subject Prefix | Uses the device name or a custom prefix. |
| Send Test Email | Sends a message to a specified recipient to verify settings. |

<Callout title="Dependency" type="warn">
  Two-step verification requires email notifications. If verification is enforced, close it before disabling email service.
</Callout>

### Provider presets

Gmail, QQ Mail, 126 Mail, and 163 Mail use a sender email and SMTP authorization code. Presets commonly use SSL port 465; ensure outbound firewall rules permit it.

### Custom email

| Field | Description |
| --- | --- |
| SMTP server | Required provider address. |
| Port | Required; common values are 25 for none, 465 for SSL, and 587 for TLS. |
| Security type | None, SSL, or TLS. |
| Username/password | Required SMTP credentials. |
| Sender name | Optional display name. |
| Sender email | Required external sender address. |

### How to get an email authorization code

An SMTP authorization code is a dedicated password generated by a mail provider for third-party email clients. It may be called an **app password**, **App Password**, or **app-specific password**, and it usually is not the mailbox login password. Copy it immediately and enter it in the system's authorization-code or password field.

Before generating one, sign in to the provider's webmail, complete account security verification, and enable the two-step or secondary verification required by the provider.

| Email service | How to get the authorization code or app password | SMTP configuration reference |
| --- | --- | --- |
| Gmail | Open your Google Account's **Security** settings, enable **2-Step Verification**, open **App passwords**, enter a purpose, and generate the password. Administrators must permit app passwords for organization accounts. | Select the Gmail preset. |
| QQ Mail | In the web version, go to **Settings** → **Account**, enable POP3/IMAP/SMTP, complete security verification as prompted, and generate an authorization code. | Select the QQ Mail preset. |
| Outlook.com, Hotmail, Live | Open your Microsoft account's **Security** settings, select **Advanced security options**, and create a new app password under **App passwords**. | Custom email: `smtp-mail.office.com`, port `587`, security type `TLS`. |
| Microsoft 365 work or school account | Ask an administrator to confirm that SMTP sending is allowed, then create an app password according to the organization's multi-factor verification policy. Some organizations disable app passwords or SMTP. | Custom email: `smtp.office365.com`, port `587`, security type `TLS`. |
| 163 Mail | In the web version, go to **Settings** → **POP3/SMTP/IMAP**, enable SMTP, and generate a client authorization password. | Select the 163 Mail preset. |
| Yahoo Mail | Open the Yahoo account's **Account Security** settings and generate an app password. | Custom email: `smtp.mail.yahoo.com`, port `465/SSL` or `587/TLS`. |
| iCloud Mail | Open the Apple Account's **Sign-In and Security** settings and generate an **App-Specific Password**. Two-factor authentication must be enabled first. | Custom email: `smtp.mail.me.com`, port `587`, security type `TLS`. |
| AOL Mail | Open the AOL account's **Security** settings and generate an app password. | Custom email: `smtp.aol.com`, port `465/SSL` or `587/TLS`. |
| Zoho Mail | Open the Zoho account's security settings and generate an app password under **App Passwords**. | Custom email: `smtp.zoho.com`, port `465/SSL` or `587/TLS`; for custom domains or regional accounts, use the address provided by Zoho. |
| 126 Mail | In the web version, go to **Settings** → **POP3/SMTP/IMAP**, enable SMTP, and generate a client authorization password. | Select the 126 Mail preset. |

<Callout title="Provider policies may change" type="info">
  Provider entry names, account types, and administrator policies may change. If you cannot generate an app password or a test email still fails, use a mailbox whose provider explicitly permits SMTP sending, or ask the mail administrator to confirm outbound policy.
</Callout>

### Test email

Enter a valid recipient and send. If the message does not arrive, check the authorization code, port, security type, and firewall outbound rule.

## Notification language

![Notification Language](/images/common/app-guide/settings-img/notification-language.png)

Choose Simplified Chinese, Traditional Chinese, English, Japanese, Korean, German, French, or Spanish, then select **Apply**. This controls notification content language, not necessarily the desktop interface language.

## Email troubleshooting

| Symptom | Check |
| --- | --- |
| Authorization-code error | SMTP enabled, complete code copied, and login password not used accidentally. |
| SMTP timeout | Server address, port, security type, and outbound firewall rule. |
| SSL port with TLS selected | Match provider documentation; commonly 465/SSL and 587/TLS. |
| Message in spam | Sender name, SPF/DKIM/DMARC, and custom-domain DNS. |
| Test succeeds but code missing | Recipient spam folder, language, two-step policy, and delay. |
| Disable blocked | Two-step verification depends on email; close the policy first. |

## Custom-SMTP checklist

Confirm the SMTP address, matching port/security type, username, password or authorization code, sender email, outbound port, and test delivery. Check the recipient spam folder after sending.

## Language and multiple devices

Notification language affects future email/SMS content. Historical messages are not retranslated. When multiple devices share a sender, use distinct subject prefixes such as device name, location, or purpose.

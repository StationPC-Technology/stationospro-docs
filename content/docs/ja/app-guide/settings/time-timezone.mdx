時間とタイムゾーンページは、デバイスの時刻を正確に保つために使用します。正確な時刻は、ログの並べ替え、スケジュールタスク、証明書の検証、二要素認証、HTTPS 通信にとって非常に重要です。

![Time](/images/ja/app-guide/settings-img/time.png)

## タイムゾーン

| オプション | 説明 |
| --- | --- |
| Timezone | デバイスが所在するタイムゾーンを選択します（例：`(UTC+08:00) Beijing, Chongqing, Hong Kong, Urumqi`）。 |
| 検索／フィルター | タイムゾーンのドロップダウンでは都市名または UTC オフセットで検索でき、目的のタイムゾーンをすばやく特定できます。 |

デバイスの設置地域と使用者の所在地が異なる場合は、デバイスの実際の設置場所に合わせてタイムゾーンを設定し、タスクの実行時刻が現地の想定とずれないようにすることをおすすめします。

## 時間

### 自動同期

| オプション | 説明 |
| --- | --- |
| Auto Sync | NTP サーバーが定期的にシステム時刻を校正します。日常的な使用に推奨します。 |
| NTP サーバー | `pool.ntp.org`、`time.google.com`、`time.cloudflare.com`、`time.apple.com`、`time.windows.com`、`time.nist.gov`、`ntp.tencent.com`、`ntp.aliyun.com` などを選択でき、カスタムの NTP アドレスを入力することもできます。 |
| 現在の時刻 | ページに現在のシステム時刻がリアルタイムで表示されます。 |

<Callout title="ヒント" type="info">
  デバイスが選択した NTP サーバーにアクセスできない場合は、DNS、ファイアウォールのアウトバウンドルール、UDP 123 ポートを確認してください。中国本土のネットワーク環境では、NTP サービスプロバイダーが提供するアドレスを優先して試すことができます。
</Callout>

### 手動設定

| オプション | 説明 |
| --- | --- |
| Manual Set | 日付と時刻を手動で指定します。 |
| Date | 日付を選択します。形式は `2026-10-14` などです。 |
| Time | 時刻を入力します。形式は `17:46:26` などです。 |
| 警告の表示 | 時刻を正確に保つようシステムが注意を促します。ずれが大きすぎると、ネットワークリクエストの失敗やサービス異常を引き起こす可能性があります。 |

手動設定は、分離されたネットワークや NTP にアクセスできない環境に適しています。設定が完了したら **適用** をクリックして保存します。

<Callout title="注意" type="warn">
  証明書の有効期間外の時刻や、実際の時刻と大きく異なる時刻を設定しないでください。HTTPS、リモートアクセス、更新チェック、二要素認証が失敗する可能性があります。
</Callout>

## NTP と手動設定の選択

| シーン | 推奨 |
| --- | --- |
| インターネットにアクセスできる | 自動同期。 |
| 分離された内部ネットワーク | 手動設定、または内部の NTP サーバーに接続します。 |
| 時刻のずれで証明書の検証に失敗する | まず利用可能な NTP に切り替え、時刻が証明書の有効範囲に戻ったことを確認します。 |
| スケジュールタスクの実行時刻がずれる | タイムゾーンと NTP を確認し、時刻だけを変更しないでください。 |
| 複数のタイムゾーンにまたがるチーム | デバイスの実際の設置タイムゾーンに合わせて設定し、ログの時刻を統一します。 |

## 時刻異常の影響

| 機能 | 考えられる影響 |
| --- | --- |
| HTTPS／証明書 | 証明書が未発効または満了済みとして検証に失敗します。 |
| 二要素認証／OTP | 動的コードの時間枠が一致しなくなります。 |
| ログ監査 | イベントの順序と発生日時が信頼できなくなります。 |
| スケジュールタスク | 電源オン／オフ、バックアップタスクが早まったり遅れたりします。 |
| クラウド同期／API | リクエストの署名やトークンの検証に失敗します。 |
| 更新チェック | 更新元がリクエストを拒否する場合があります。 |

## トラブルシューティングの推奨

1. まずタイムゾーンを確認し、次に時刻を確認します。2 つの誤りが重なると判断が難しくなります。
2. NTP が反映されない場合は、DNS と UDP 123 のアウトバウンドをテストします。
3. NTP サービスプロバイダーを変更した後は、1 回の同期周期を待ちます。
4. 手動設定後は直ちに適用し、一時的な時刻のまま長時間放置しないでください。
5. 時刻を変更した後はクライアントで再ログインし、セッションとキャッシュを更新してください。

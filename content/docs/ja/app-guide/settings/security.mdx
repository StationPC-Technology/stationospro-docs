セキュリティページには **ポート設定**、**アカウントセキュリティ**、**保護**、**ファイアウォール**、**証明書**、**デバイス分析** の 6 つのタブがあり、システムの入口を厳格にし、アクセス元を制御し、通信を暗号化し、プライバシー関連のスイッチを確認するために使用します。

## ポート設定

![Port Settings](/images/ja/app-guide/settings-img/security-port-settings.png)

### 現在の情報

ページには現在の Web 管理入口のポートが表示されます。

| 項目 | デフォルト値 | 説明 |
| --- | --- | --- |
| HTTP ポート | 9500 | HTTP で管理画面にアクセスします。 |
| HTTPS ポート | 9501 | HTTPS で管理画面にアクセスします。 |

### ポート設定ダイアログ

| オプション | 説明 |
| --- | --- |
| HTTP ポート番号 | 必須。範囲は 1～65535 で、HTTPS ポートと同じにすることはできません。 |
| HTTPS ポート番号 | 必須。範囲は 1～65535 です。強制 HTTPS またはデフォルトポートのリダイレクトを有効にする場合は 0 にできません。 |
| 強制 HTTPS 接続 | HTTP 接続を HTTPS 接続にリダイレクトします。 |
| ポート 80 と 443 のリダイレクト | 80 を HTTP ポートへ、443 を HTTPS ポートへリダイレクトします。有効にすると、デバイスへのアクセス時にポート番号を省略できます。 |

<Callout title="注意" type="warn">
  デフォルトポートのリダイレクトを有効にする場合、HTTP/HTTPS ポートに 80 または 443 を使用することはできません。ポートを変更した後は、新しいポートで管理画面を開き直し、ファイアウォールやルーターの転送ルールが同期して更新されていることを確認してください。
</Callout>

## アカウントセキュリティ

アカウントセキュリティページでは、システムレベルの二要素認証ポリシーを制御します。

![Account Security](/images/ja/app-guide/settings-img/security-account-security.png)

| オプション | 説明 |
| --- | --- |
| 二要素認証を必須にする | 有効にすると、ポリシーの対象となるユーザーはログイン時に 2 段階目の OTP 認証を完了する必要があります。 |
| すべてのユーザー | ポリシーをすべてのユーザーに適用します。 |
| 管理者のみ | 管理者アカウントのみに二要素認証を必須にします。 |
| 指定ユーザー | 選択したユーザーまたはユーザーグループのみに二要素認証を必須にします。 |
| 指定ユーザーの編集 | ユーザー／ユーザーグループ選択画面でポリシーの対象を追加または削除します。 |

<Callout title="前提条件" type="info">
  二要素認証はメール通知サービスに依存します。有効にする前に、「システム設定 → 通知設定」で送信元メールアドレスを設定してください。メールサービスをオフにすると、二要素認証の確認コードを送信できなくなる場合があります。
</Callout>

## 保護

保護ページは、異常なログイン IP を自動的にブロックし、許可リストとブロックリストを管理するために使用します。

![Protection](/images/ja/app-guide/settings-img/security-protection.png)

### 異常 IP のブロック

| オプション | 説明 |
| --- | --- |
| サービスのスイッチ | 有効にすると、システムがルールに従って異常な IP のログインを遮断します。 |
| ルールの編集 | 自動ブロックのしきい値、集計時間、ブロック解除時間を設定します。 |

### 自動ブロックのルール

| 項目 | デフォルト値 | 範囲 | 説明 |
| --- | --- | --- | --- |
| ログイン試行回数 | 10 回 | 1～100 | ブロックを発動するために必要な失敗回数。 |
| 設定時間内 | 5 分 | 1～10080 分 | 失敗回数を集計する時間枠。 |
| 自動ブロック解除のルール | 1 時間 | 30 分／1 時間／1 日／7 日／30 日／無期限 | ブロックされた IP のブロック解除時間。 |

### 許可リストとブロックリスト

| リスト | 優先度と役割 |
| --- | --- |
| 許可リスト | リスト内の IP/CIDR は常に接続とログインが許可され、ブロックルールの影響を受けません。優先度はブロックリストより高くなります。 |
| ブロックリスト | リスト内の IP/CIDR は常に接続とログインが制限されます。 |

リストのテーブルには、クライアント IP、最終アクセス時刻、有効期限（ブロックリスト）、無期限の表示、備考が表示されます。次の操作をサポートします。

| 操作 | 説明 |
| --- | --- |
| 追加 | 1 つまたは複数の IP/CIDR を入力します。複数のアドレスは改行またはカンマで区切ります。ブロックリストではブロック解除時間を選択できます。 |
| 備考 | 最大 180 文字。送信元や用途を記録するために使用します。 |
| 削除 | 1 つまたは複数のレコードを選択して削除し、対応する制限を解除します。 |

## ファイアウォール

ファイアウォールページは、インバウンドルールとアウトバウンドルールに従ってネットワークトラフィックを制御します。

![Firewall](/images/ja/app-guide/settings-img/security-firewall.png)

### 基本設定

| オプション | 説明 |
| --- | --- |
| ファイアウォールのスイッチ | 有効にすると、システムがインバウンド／アウトバウンドルールに従ってトラフィックを制御します。 |
| 詳細設定 | 動作モードと LAN のデフォルト許可を設定します。 |

### 詳細設定

| オプション | 説明 |
| --- | --- |
| 動作モード | Auto は XDP native モードを優先的に選択します。Generic は従来のカーネルネットワークスタックを使用します。互換性の問題が発生した場合に切り替えられます。 |
| LAN | 「デフォルトでアクセスを許可」を有効にすると、LAN のトラフィックがデフォルトで許可され、管理画面が誤って遮断される可能性を低減できます。 |

### インバウンドルールとアウトバウンドルール

| 項目 | 説明 |
| --- | --- |
| ネットワーク接続 | すべてのインターフェース、または指定したネットワークインターフェース。 |
| ポート | 単一ポート、カンマ区切りのポート、または範囲（例：`80`、`443`、`1-65535`）。 |
| プロトコル | すべて、TCP、UDP、ICMP。 |
| 送信元 IP／宛先 IP | カスタム IP または CIDR。インバウンドは送信元 IP、アウトバウンドは宛先 IP を参照します。 |
| 権限 | 許可または拒否。 |
| ステータス | 有効または無効。 |
| 備考 | ルールの用途の説明。 |
| 順序 | ルールはドラッグして並べ替えられ、上にあるほど優先度が高くなります。 |
| 以下のルールがいずれも一致しない場合 | デフォルトのアクセス許可またはデフォルトのアクセス拒否を設定します。 |

<Callout title="危険な操作" type="error">
  誤ったファイアウォールルールにより、管理画面、リモートアクセス、アプリサービスに到達できなくなる可能性があります。設定前に現在の管理接続を保持し、管理ポート、SSH ポート、LAN を優先して許可してください。
</Callout>

## 証明書

証明書ページは、システムの HTTPS、FTPS、WebDAV、リモートアクセスで使用する証明書を管理するために使用します。

![Certificate](/images/ja/app-guide/settings-img/security-certificate.png)

### 証明書一覧

| 項目 | 説明 |
| --- | --- |
| 証明書名 | ユーザーが識別できる名前。 |
| 証明書の種類 | システムの自己署名証明書、Let's Encrypt 証明書、インポートした証明書。 |
| 発行機関 | 証明書の発行者。 |
| 代替ドメイン | 証明書がカバーする他のドメイン名。ない場合は `-` と表示されます。 |
| 有効期限 | 満了日時。 |
| 自動更新 | システム証明書または Let's Encrypt 証明書は、満了前に自動更新できます。 |
| ステータス | 有効、まもなく満了、満了済み。 |
| 操作 | 詳細の表示／編集、更新、ダウンロード、削除。削除後は復元できません。 |

### 証明書の追加

| 方式 | 説明 |
| --- | --- |
| 証明書のインポート | ローカルからアップロードするか、NAS から証明書ファイル、秘密鍵ファイル、任意の中間証明書を選択します。既に CA 発行の証明書を持っているユーザーに適しています。 |
| 証明書の取得 | Let's Encrypt から無料の証明書を取得し、自動更新します。メールアドレスを入力し、DDNS ドメインまたはカスタムドメインとサービスプロバイダーを選択する必要があります。 |

### Let's Encrypt 証明書取得の注意点

- 無料証明書には申請の頻度と数の制限があります。
- HTTP 検証では 80 ポートを NAS に転送する必要があり、DNS 検証ではサービスプロバイダーの対応が必要です。
- ドメイン名は現在の公衆 IP を正しく指している必要があります。
- 取得成功後、システムは証明書の満了前に自動更新します。

### サービス設定

**Service Config** は、FTPS、WebDAV、リモートアクセスの証明書に対応する証明書を選択するために使用します。確認すると、関連サービスが選択した証明書で暗号化接続を確立します。

## デバイス分析

デバイス分析ページには、プライバシーに関連する 2 つのスイッチがあります。

![Device Analytics](/images/ja/app-guide/settings-img/security-device-analytics.png)

| オプション | 説明 |
| --- | --- |
| デバイス分析改善プログラムに参加 | システムが一部の匿名使用データを収集し、製品の使用状況の分析、安定性の向上、機能の改善に使用します。いつでも参加を終了できます。 |
| webfind サービスを有効化 | 有効にすると、LAN 内で Station OS デバイスを検出できます。システムはこのサービスを提供するために IP アドレスとポート情報を収集します。 |

2 つの説明はどちらもプライバシーポリシーにリンクしています。データ収集への参加や LAN 検出機能の提供を望まない場合は、対応するスイッチをオフにできます。

<Callout title="セキュリティベースラインの推奨" type="info">
  HTTPS／強制 HTTPS、二要素認証、異常 IP 保護、ファイアウォールを有効にすることをおすすめします。必要なポートのみを開放し、証明書の自動更新を設定し、外部ネットワークからのアクセスには Station ID または VPN を優先してください。
</Callout>

## ポートポリシーの推奨

| シーン | 推奨 |
| --- | --- |
| 家庭の LAN | HTTP/HTTPS を維持し、信頼できるデバイスのみログイン状態を保存します。 |
| インターネットまたは共有ネットワーク | HTTPS／強制 HTTPS を有効にし、平文でのパスワード送信を避けます。 |
| ポートを省略したいだけ | 80/443 のリダイレクトを有効にしますが、ルーターとファイアウォールのルールが同期していることを確認してください。 |
| デフォルトポートを変更 | 1024～65535 の中で未使用のポートを選択し、SMB/FTP/SSH と競合しないようにします。 |
| リモートアクセス | Station ID または VPN を優先し、管理ポートを直接公開しないでください。 |

## 二要素認証ポリシーの比較

| 範囲 | 利点 | 適用 |
| --- | --- | --- |
| すべてのユーザー | セキュリティベースラインが最も高くなります。 | 機密ファイルがある、または複数人で使用するデバイス。 |
| 管理者のみ | セキュリティと一般ユーザーの利便性を両立します。 | 家庭用デバイス、または一般アカウントの権限が低い場合。 |
| 指定ユーザー | リスクの高いアカウントを的確に管理します。 | バックアップ、財務、運用などの特殊なアカウントのみ。 |

ポリシーを有効にすると、指定範囲のユーザーは個人設定で認証アプリまたはメール認証の設定を完了する必要があります。管理者は先にメールサービスが利用可能であることを確認してください。

## IP 保護設計の推奨

- **許可リスト**：固定のオフィスネットワーク、家庭の出口、VPN の出口、踏み台サーバーのアドレス。
- **ブロックリスト**：ログインを繰り返し試みる送信元、侵害されたネットワークセグメント、明確なスキャン元。
- **しきい値**：家庭用デバイスでは比較的厳しくできます。複数人で使用する場合やプロキシ出口の環境では、しきい値を小さくしすぎないようにしてください。
- **ブロック解除時間**：重要なデバイスでは長めに設定できます。一時的なネットワークでは短時間にして復旧しやすくできます。
- **VPN の注意**：出口 IP が変わると検出結果に影響します。必要に応じて固定出口またはカスタム検出アドレスを使用してください。

## ファイアウォールルール設計の流れ

1. まず管理ポート、SSH ポート、LAN のネットワークセグメントを許可します。
2. HTTPS、WebDAV、FTPS など、インバウンドサービスとポートを明確にします。
3. 送信元 IP、プロトコル、ポートに基づいて最小範囲のルールを作成します。
4. 拒否ルールを使用して、明確に不要な送信元を遮断します。
5. ドラッグして優先度を調整し、上にあるほど先に照合されます。
6. デフォルトポリシーを設定します。ファイアウォールに不慣れな場合は、まずアクセス許可を維持し、ルールを検証してから厳格化してください。
7. 新しいルールが信頼できることを確認するまで、接続中の管理セッションを 1 つ保持してください。

## 証明書のトラブルシューティング

| 問題 | 確認事項 |
| --- | --- |
| ブラウザーで証明書のドメイン名が一致しないと表示される | アクセスするドメイン名と証明書の代替ドメインが一致しているか。 |
| Let's Encrypt の申請に失敗 | ドメイン名解決、80 ポートの転送、API 権限、頻度制限。 |
| HTTPS でアクセスできない | HTTPS ポート、ファイアウォール、サービス設定で証明書が選択されているか。 |
| 証明書が自動更新されない | システム時刻、DNS 解決、80/443 への到達性。 |
| インポート後にクライアントが信頼しない | 中間証明書の不足、または自己署名証明書の使用。 |

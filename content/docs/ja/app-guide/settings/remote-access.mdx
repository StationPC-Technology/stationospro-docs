リモートアクセスページは **リモートアクセス** と **DDNS** に分かれています。Station ID は公式の中継サービスを利用してすばやくアクセスするのに適しており、DDNS は既にドメインを所有していて、独自ドメインで公衆 IP を解決したいユーザーに適しています。

## Station ID リモートアクセス

![Remote Access](/images/ja/app-guide/settings-img/remote-access.png)

### 基本設定

| 機能／項目 | 説明 |
| --- | --- |
| Station ID リモートアクセスのスイッチ | 有効にすると、デバイスはインターネット経由でリモートアクセスできます。有効化または無効化の前に本人認証が必要で、ユーザー規約とプライバシーポリシーへの同意が必要です。 |
| Station ID | リモートアクセスの識別子。4～30 文字で、数字、小文字の英字、ハイフンのみ使用でき、ハイフンを先頭または末尾に置くことはできません。 |
| 紐付け済みメールアドレス | 現在紐付けられているリモートアクセスアカウントのメールアドレスを表示します。リモートアクセスを有効にするには、先にメールアドレスを紐付ける必要があります。 |
| 変更／編集 | Station ID または編集の入口をクリックすると ID を変更できます。ID が既に使用されている場合は変更が必要です。 |

### リモートアクセス方式

| 方式 | 使用方法 |
| --- | --- |
| Web | ブラウザーで `https://scnas.cloud/<Station ID>/web` にアクセスします。 |
| クライアント | StationCloud クライアントで Station ID を入力し、デバイスを追加してアクセスします。 |

### アカウントの紐付け解除

アカウントの安全を確保するため、紐付けの解除には紐付け済みの StationCloud／思特云アカウントへのログインが必要です。

1. ブラウザーで `login.stationpc.com` を開きます。
2. デバイスに紐付けられたアカウントでログインします。
3. 「マイデバイス」またはアプリ内のデバイス管理に移動します。
4. 現在のデバイスを選択して紐付けを解除します。

<Callout title="注意" type="warn">
  リモートアクセスをオフにすると、現在のリモート接続が切断されます。アカウントの紐付けを解除するとリモートアクセスは使用できなくなり、再度使用するには改めて紐付けと認証を完了する必要があります。
</Callout>

## DDNS

DDNS は定期的に公衆 IP を検出し、その変化をドメイン名解決サービスプロバイダーに同期します。設定がない場合、ページには空の状態が表示され、**設定を追加** をクリックできます。

![DDNS](/images/ja/app-guide/settings-img/ddns.png)

### 設定一覧

| 項目 | 説明 |
| --- | --- |
| サービスプロバイダー | DNS サービス提供元（例：Cloudflare、DNSPod.cn、No-IP.com、Duck DNS、FreeDNS、ChangeIP.com、DynDNS など）。実際の一覧はサーバーから返されます。 |
| ドメイン | 現在の DDNS レコードに紐付けられたドメイン。 |
| ステータス | 更新済み、無効、未接続、接続中、異常。 |
| 最終更新時刻 | 最後に IP を検出または同期した時刻。 |
| 操作 | 設定の編集、即時更新、有効化／無効化、削除。削除後は復元できません。 |

### 設定の追加／編集

#### 基本設定

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| サービスプロバイダー | はい | ドメイン名解決サービスプロバイダーを選択します。追加後はサービスプロバイダーを直接変更できません。 |
| ドメイン | はい | 完全なドメイン名を入力します。ドメイン名は形式に適合し、既存の DDNS 設定と重複してはなりません。 |
| AccessKey/API Token/アカウント | サービスプロバイダーによる | サービスプロバイダーが要求するアカウントまたは AccessKey。項目名はサービスプロバイダーによって異なります。 |
| SecretKey/API Secret/パスワード | サービスプロバイダーによる | サービスプロバイダーのキー。編集時に空欄にすると、保存済みのキーを引き続き使用します。 |
| IPv4 | はい、または IPv6 が少なくとも 1 つ | デフォルトは「自動」で、検出された公衆 IPv4 を表示します。インターフェースアドレスやカスタム検出アドレスも選択できます。 |
| IPv6 | はい、または IPv4 が少なくとも 1 つ | デフォルトはオフです。自動の公衆 IPv6、インターフェースの IPv6、カスタム検出アドレスを選択できます。 |

<Callout title="VPN に関するヒント" type="info">
  ページには、VPN を有効にしていると外部 IP アドレスの確認が不正確になる場合があると記載されています。VPN を一時的にオフにして再設定するか、正しい外部 IP アドレスを手動で入力してください。
</Callout>

#### 詳細設定

| 項目 | 説明 |
| --- | --- |
| 更新時間 | 1、5、10、15、30、60 分ごとに IP の更新を定期的に確認します。 |
| 接続テスト | 設定を即時に検証します。結果は未接続、接続中、更新済み、異常のいずれかで表示されます。 |

#### 下部のオプション

| オプション | 説明 |
| --- | --- |
| 設定を有効化 | この DDNS 設定を有効にするかどうかを制御します。 |

<Callout title="利用の前提" type="warn">
  DDNS はドメイン名解決のみを担当し、ルーターの NAT を自動的に越えることはありません。インターネットから NAS にアクセスする必要がある場合は、ルーターでポート転送を設定するか、Station ID リモートアクセスを使用する必要があります。公開サービスでは、必ず HTTPS、強力なパスワード、二要素認証を有効にしてください。
</Callout>

## Station ID の使用ルール

| 項目 | 説明 |
| --- | --- |
| 文字のルール | 4～30 文字。小文字の英字、数字、ハイフン。ハイフンを先頭または末尾に置くことはできません。 |
| 一意性 | 他のデバイスで既に使用されている ID は再利用できません。 |
| 生成条件 | リモートアクセスサービスを有効にし、紐付けを完了する必要があります。 |
| 変更の影響 | 古い Web／クライアントのアドレスは直ちに無効になり、新しい ID を使用する必要があります。 |
| セキュリティ上の関係 | Station ID はパスワードではありません。引き続きデバイスのローカルアカウントでのログインが必要です。 |
| 紐付け解除の影響 | リモートアクセスは使用できなくなり、再度使用するには改めて紐付けが必要です。 |

## リモートアクセスを有効にする一般的な流れ

1. 通知設定で利用可能なメールアドレスを設定します。
2. リモートアクセスページでメールアドレスを紐付け、認証を完了します。
3. ルールに適合する Station ID を設定します。
4. ユーザー規約とプライバシーポリシーに同意します。
5. リモートアクセスサービスを有効にします。
6. 外部ネットワークのブラウザーまたはクライアントでアクセスをテストします。
7. HTTPS／強力なパスワード／二要素認証の有効化をおすすめします。

## DDNS の項目詳細

| 項目 | 説明 |
| --- | --- |
| サービスプロバイダー | DNS API のアドレスと認証項目を決定します。追加後にむやみに再作成せず、編集時にサービスプロバイダーを直接変更しないことをおすすめします。 |
| ドメイン | そのサービスプロバイダーの下で管理されている完全なドメイン名である必要があります。 |
| AccessKey/API Token | サービスプロバイダーが DNS 操作権限を付与する認証情報です。最小限の DNS 権限のみを付与することをおすすめします。 |
| SecretKey/API Secret | AccessKey とペアになります。編集時に空欄にすると、保存済みのキーを引き続き使用できます。 |
| IPv4 自動検出 | 公共の検出サービスを使用して公衆 IPv4 を取得します。 |
| IPv4 インターフェースアドレス | デバイスが指定するインターフェースアドレスを使用します。固定の公衆 IP がある環境に適しています。 |
| IPv4 カスタム URL | カスタムサービスが返す IP を使用します。NAT／プロキシ環境に適しています。 |
| IPv6 | デフォルトはオフです。自動検出またはインターフェースアドレスを使用できます。 |
| 更新時間 | 短いほど反映が速くなりますが、リクエストの頻度が高くなります。 |

## DDNS のトラブルシューティング

| 現象 | 確認事項 |
| --- | --- |
| 接続テストが異常 | AccessKey/Secret、ドメインの管理元、API 権限、サーバーのネットワーク。 |
| ドメイン名解決の IP が変わらない | ローカル DNS キャッシュ、TTL、検出サービスが正しい公衆 IP を取得しているか。 |
| ドメイン名解決は正しいがアクセスできない | ルーターのポート転送、ファイアウォール、サービスポート、ISP によるブロックの有無。 |
| VPN 環境で検出が誤る | VPN を一時的にオフにするか、カスタム IP 検出アドレスを使用します。 |
| IPv6 が使用できない | ルーター／事業者の IPv6 プレフィックス、インターフェースアドレス、ファイアウォールの許可。 |

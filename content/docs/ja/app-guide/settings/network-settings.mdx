ネットワーク設定ページは **一般** と **ネットワーク接続** に分かれています。一般ページはグローバルなゲートウェイ、DNS、高度な解決ポリシーを担当し、ネットワーク接続ページは各ネットワークカードの IP パラメーター、ブリッジ、リンクアグリゲーションを担当します。

## 一般

![Network General](/images/ja/app-guide/settings-img/network-general.png)

### デフォルトゲートウェイ

| 項目 | 説明 |
| --- | --- |
| デフォルトゲートウェイ | 現在の IPv4 デフォルトゲートウェイ（例：`172.16.0.1`）。デバイスが他のネットワークセグメントやインターネットにアクセスする際に優先的に使用されます。 |
| IPv6 デフォルトゲートウェイ | 現在の IPv6 デフォルトゲートウェイ。未設定または使用できない場合は `-` と表示されます。 |

### DNS サーバー

| オプション | 説明 |
| --- | --- |
| DNS サーバーを手動設定 | チェックしない場合は DHCP などで自動的に DNS を取得します。チェックすると手動で入力できます。 |
| プライマリ DNS サーバー | 必須。ドメイン名解決の優先サーバー（例：`202.96.134.33`）。 |
| セカンダリ DNS サーバー | 任意。プライマリ DNS が使用できないときに使用します（例：`202.96.128.86`）。 |

### 詳細設定

| オプション | 説明 |
| --- | --- |
| マルチゲートウェイを有効化 | システムが複数のゲートウェイを使用できるようにします。デバイスが複数のネットワークセグメントや複数のアップリンクに接続するシーンに適しています。 |
| DNS 解決で IPv4 を優先 | ドメイン名に IPv4/IPv6 の両方のレコードがある場合に IPv4 を優先し、一部の IPv6 ネットワークが接続できないことによるアクセスの遅延を防ぎます。 |
| IP 競合検出を有効化 | LAN 内のアドレス競合を検出し、固定 IP が他のデバイスと競合する問題の発見に役立ちます。 |
| 適用 | クリックすると現在のページの変更を保存します。変更がない場合はボタンを使用できません。 |

<Callout title="注意" type="warn">
  現在のブラウザーがネットワーク経由でデバイスにアクセスしている場合、ゲートウェイ、DNS、ネットワークカードの IP を変更すると接続が中断する可能性があります。新しいパラメーターがルーティング可能であることを確認し、新しい IP またはコンソールから接続を復旧できるように準備してください。
</Callout>

## ネットワーク接続

![Network Connections](/images/ja/app-guide/settings-img/network-connections.png)

### ネットワークカード一覧

各ネットワークカードのカードには次の情報が表示されます。

| 項目 | 説明 |
| --- | --- |
| インターフェース名 | 例：Port 1 (`enP2p33s0`)、Port 2 (`enP4p65s0`)。 |
| 速度 | 現在のネゴシエーション速度（例：1Gbps）。 |
| デュプレックスモード | 全二重または半二重。 |
| MTU | 現在の最大転送単位（例：MTU1500）。 |
| 接続状態 | 接続済み、未接続、使用不可など。 |
| MAC アドレス | ネットワークカードのハードウェアアドレス。 |
| IPv4 アドレス／サブネットマスク／ゲートウェイ | IPv4 接続パラメーター。アドレスの横でコピーできます。 |
| DNS | IPv4 DNS サーバーの一覧。 |
| IPv6 アドレス／ゲートウェイ／DNS | IPv6 接続パラメーター。未設定の場合は `-` と表示されます。 |
| ネットワークの種類 | イーサネット、ブリッジ、リンクアグリゲーションなど。 |

### ネットワークカードの編集

ネットワークカードのカードにある編集ボタンをクリックすると、次の項目を変更できます。

| 設定 | モード | 項目とルール |
| --- | --- | --- |
| IPv4 | 自動 | DHCP によりアドレス、マスク、ゲートウェイ、DNS を自動取得します。手動入力ボックスは無効になります。 |
| IPv4 | 手動 | IPv4 アドレスとサブネットマスクが必須です。ゲートウェイ、プライマリ DNS、セカンダリ DNS を入力できます。アドレスは有効な IPv4 形式である必要があり、サブネットマスクは連続したマスクである必要があります。 |
| MTU | 自動 | システムのデフォルト MTU を使用します。 |
| MTU | 手動 | 1280～9000 を入力できます。変更前に、スイッチとリンクが対応するフレームサイズをサポートしていることを確認してください。 |

### ブリッジの作成

**Create Bridge** を使用すると、2 つ以上の物理ネットワークカードを同じブリッジネットワークに追加できます。

1. **Create Bridge** をクリックします。
2. 使用可能な物理ネットワークカードを少なくとも 2 つ選択します。
3. 確認すると、システムがブリッジインターフェースを作成します。
4. 作成後は、通常のインターフェースと同じように IP パラメーターを編集できます。

<Callout title="ヒント" type="info">
  ブリッジは、仮想マシン、コンテナ、分離されたネットワークを物理 LAN に直接接続するためによく使用されます。ブリッジを作成すると元のネットワークカードの接続方式が変わる可能性があるため、現在の管理用ネットワークカードを誤って選択しないよう注意してください。
</Callout>

### リンクアグリゲーションの作成

**Create Link Aggregation** を使用すると、複数のネットワークカードを 1 つの論理インターフェースに統合し、帯域幅の合計やリンクのバックアップを実現できます。システムは同じ仕様のネットワークカードの使用を要求します。

| 分類 | モード | 特徴と要件 |
| --- | --- | --- |
| スイッチ設定不要 | Adaptive Load Balancing – bond6 | 推奨。システムが複数のネットワークポート間でトラフィックを自動的に分散し、スイッチのアグリゲーション対応は不要です。 |
| スイッチ設定不要 | Active/Backup – bond1 | 主系／待機系モード。バックアップポートは通常非アクティブで、主系ポートの故障時に自動的に切り替わります。信頼性は高いですが、帯域幅は合算されません。 |
| スイッチ設定が必要 | Round Robin – bond0 | トラフィックをラウンドロビンで分散し、2 つのポートで同時に転送するため、速度を大幅に向上できます。スイッチが静的アグリゲーションに対応し、正しく設定されている必要があります。 |
| スイッチ設定が必要 | Balance XOR – bond2 | ハッシュに基づいてリンクを割り当てます。スイッチが静的アグリゲーションに対応している必要があり、複数スイッチのシーンではスタックと適切な設定が必要です。 |
| スイッチ設定が必要 | Dynamic Link Aggregation – bond4 | IEEE 802.3ad 動的アグリゲーション。スイッチが LACP に対応し、正しく設定されている必要があり、複数スイッチではスタックが必要です。 |

### ネットワークモードの解除

ブリッジまたはリンクアグリゲーションのインターフェースでは、その他の操作からネットワークモードを解除できます。システムはこの操作が対応する論理インターフェースに影響することを通知し、確認後にメンバーネットワークカードを復元します。

<Callout title="操作の推奨" type="warn">
  リンクアグリゲーションモードはスイッチの設定と一致している必要があります。スイッチの対応が必要なモードを選択したにもかかわらずスイッチが設定されていない場合、ネットワークが中断したり、アグリゲーションポートが繰り返し異常になったりする可能性があります。
</Callout>

## ネットワーク変更前の準備

1. 現在の IP、マスク、ゲートウェイ、DNS、MTU、インターフェース名を記録します。
2. LAN、コンソール、または 2 つ目のネットワークポートからの復旧経路があることを確認します。
3. スイッチの VLAN、ポート速度、アグリゲーション、ファイアウォールポリシーを確認します。
4. 新しい固定 IP が他のデバイスと競合しないことを確認します。
5. リンクアグリゲーションを使用する場合は、先にスイッチ側で対応する設定を完了し、モードを照合します。
6. 複数のネットワーク条件を同時に変更しないでください。変更するたびに、まず接続を検証してください。

## インターフェース状態の読み方

| 状態／項目 | 意味 |
| --- | --- |
| Connected | リンクが確立され、アドレスを取得できています。 |
| Disconnected | ネットワークケーブル／リンクが確立されていません。 |
| 1Gbps / 2.5Gbps / 10Gbps | 現在のネゴシエーション速度。両端のデバイスとケーブルによって制限されます。 |
| Full Duplex | 同時に送受信できます。半二重は効率が低くなります。 |
| MTU1500 | 標準イーサネットの MTU。ジャンボ MTU は全リンクでの対応が必要です。 |
| `-` | 値を取得していない、またはそのプロトコルスタックが設定されていません。 |
| Bridge | 複数の物理インターフェースで構成されたブリッジ。 |
| Bond | 複数のネットワークカードで構成されたリンクアグリゲーションの論理インターフェース。 |

## ブリッジとリンクアグリゲーションの選択

| 要件 | 選択 |
| --- | --- |
| 仮想マシン／コンテナを物理 LAN に直接参加させる | ブリッジ。 |
| 2 つのネットワークカードの帯域幅を合算し、スイッチ設定を不要にする | bond6。 |
| 主系／待機系の災害対策を優先する | bond1。 |
| スイッチで静的アグリゲーションを設定済みで、同時スループットを追求する | bond0 または bond2。 |
| スイッチが LACP に対応し、標準的な動的アグリゲーションが必要 | bond4。 |
| NAS の IP/DNS のみを変更する | 通常のインターフェース編集を行い、ブリッジやアグリゲーションを作成しないでください。 |

## 接続を復旧する一般的な方法

- 変更していない別のネットワークポートの IP でアクセスする。
- パソコンを同じ VLAN／同じネットワークセグメントに接続し、デバイスを再スキャンする。
- ルーターの DHCP リース一覧から新しいアドレスを探す。
- DNS のみに異常がある場合は、一時的に IP で直接アクセスする。
- アグリゲーションポートが接続できない場合は、メンバーポートを切断してシングルポートで設定を復旧する。
- ネットワーク設定の重大な誤りがある場合は、アップデートと復元でネットワークのリセットを検討する。

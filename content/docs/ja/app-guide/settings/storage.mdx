ストレージ領域ページは **ストレージ領域** と **SSD キャッシュアクセラレーション** に分かれています。ストレージ領域タブは、1 台または複数のハードディスクで構成されるボリュームの作成と管理に使用します。SSD キャッシュタブは、高速な SSD を HDD ボリュームのキャッシュとして使用し、ホットデータへのアクセス性能を向上させるために使用します。

## ストレージ領域タブ

![Storage](/images/ja/app-guide/settings-img/storage.png)

### ストレージボリューム一覧

各ストレージボリュームのカードには次の情報が表示されます。

| 項目 | 説明 |
| --- | --- |
| 名前 | ストレージボリューム名（例：Storage volume1）。 |
| 健康状態 | Normal、Degraded などの状態。異常時はできるだけ早くハードディスクを確認してください。 |
| ストレージモード／RAID | Basic、JBOD、RAID0、RAID1、RAID5、RAID6、RAID10 など。 |
| 容量 | 使用済み容量／総容量。 |
| ハードディスクの種類 | HDD、SSD など。 |
| インターフェース | SATA、NVMe など。 |
| ファイルシステム | 現在のボリュームが使用するファイルシステム（例：Btrfs）。 |
| 使用中のハードディスク | そのボリュームを構成するハードディスクと容量を表示します。ハードディスクをクリックすると対応する情報を確認できます。 |

### ストレージボリュームの操作

ストレージボリュームのカードまたはその他のメニューでは、次の操作を利用できる場合があります。

| 操作 | 説明 |
| --- | --- |
| ストレージ領域の作成 | 空きハードディスクを新しいストレージボリュームとして初期化します。作成過程で選択したハードディスクがフォーマットされます。 |
| ストレージモードの変更 | 互換性がある条件で RAID タイプを変更します。ハードディスクの追加または削除が必要になる場合があります。 |
| ハードディスクの追加 | 対応する RAID ボリュームの容量を拡張します。新しいハードディスクはフォーマットされます。 |
| ホットスペアの追加／削除 | RAID ボリュームに予備のハードディスクを指定します。メンバーディスクが故障したとき、ホットスペアが自動的に復旧に参加できます。 |
| ハードディスクの交換 | 故障時や容量アップグレードのシーンでメンバーディスクを交換します。 |
| 修復／検査 | 異常状態の調査と復旧に使用します。 |

### RAID とストレージモード

| モード | ハードディスクの要件 | 利点 | リスク／制限 |
| --- | --- | --- | --- |
| Basic | 1 台 | 単一ディスクの容量を最大限に活用 | データ保護なし。ハードディスクが故障するとそのディスクのデータは失われます |
| JBOD | 1 台以上 | 複数のハードディスクを連結して 1 つの使用可能領域にし、容量拡張が簡単 | 冗長性なし。いずれかのメンバーディスクの故障で領域全体のデータが失われる可能性があります |
| RAID 0 | 2 台以上 | 読み書き速度が最も速く、容量効率が高い | データ保護なし。いずれかのハードディスクの故障で全データが失われます |
| RAID 1 | 2 台以上 | ミラー保護により、n-1 台のディスク故障までデータを失わずに済みます | 容量効率が低い |
| RAID 5 | 3 台以上 | 性能と保護のバランスが良く、1 台のディスク故障後にパリティで復旧できます | 書き込みは比較的遅く、復旧に時間がかかります |
| RAID 6 | 4 台以上 | 二重パリティにより、同時に 2 台のディスク故障に対応 | 書き込み速度と空間効率がさらに低下します |
| RAID 10 | 4 台以上かつ偶数 | ミラー後にストライプ化し、高性能と高保護を両立 | 空間効率は約半分です |

### ファイルシステムの選択

作成ウィザードではファイルシステムを選択できます。

| ファイルシステム | 適性 |
| --- | --- |
| Btrfs | スナップショット、サブボリューム、効率的なコピーをサポートし、柔軟なバックアップとバージョン管理が必要な家庭ユーザーやライトな開発者に適しています。 |
| EXT4 | 成熟して安定しており、従来のファイルサービス、リソースが限られたデバイス、安定性を重視するオフィスのシーンに適しています。 |

### ストレージ領域作成の流れ

1. **ストレージ領域の作成** をクリックします。
2. 空きハードディスクを選択します。システムが利用可能な RAID モードと予想容量をリアルタイムで計算します。
3. ストレージモード／RAID を選択し、利用可能容量、データ保護容量などの情報を確認します。
4. ファイルシステムの形式を選択します。
5. このストレージ領域を使用できるユーザーを選択し、一般ユーザーの容量制限を設定できます。
6. 概要とフォーマットの警告を確認します。
7. 作成を開始し、フォーマットの完了を待ちます。

<Callout title="危険な操作" type="error">
  ストレージボリュームの作成、変更、拡張、交換では、選択したハードディスクがフォーマットされ、ハードディスク内のすべてのデータが削除される可能性があります。操作開始後は電源を切ったり、再起動したり、ハードディスクを抜き差ししたりしないでください。必ず事前に重要なデータをバックアップしてください。
</Callout>

## SSD キャッシュアクセラレーションタブ

SSD キャッシュはホットデータを高速な SSD に保存し、HDD の読み取り待ち時間を短縮します。この機能を使用する前に、デバイスに少なくとも 1 台の未使用 SSD が搭載されている必要があります。

![SSD Cache](/images/ja/app-guide/settings-img/storage-ssd-cache.png)

### SSD キャッシュの作成

| 設定項目 | 説明 |
| --- | --- |
| アクセラレーション対象 | 高速化する HDD ストレージボリュームを選択します。 |
| キャッシュ SSD | 空き SSD を選択します。使用可能な SSD がない場合は、先にハードディスクを搭載するか解放する必要があります。 |
| キャッシュ名 | デフォルトでは自動生成されますが、用途に応じて命名することもできます。 |
| キャッシュモード | 読み取り専用キャッシュまたは読み書きキャッシュ。 |
| キャッシュ RAID | 複数の SSD がある場合はキャッシュの RAID モードを選択できます。 |
| キャッシュ容量 | 容量の最大化またはカスタム容量を選択できます。残りの容量は他のボリュームに引き続き割り当てられます。 |
| リスクの確認 | キャッシュの作成、SSD のフォーマット、読み書きキャッシュの停電リスクを理解したうえで確認する必要があります。 |

### キャッシュモードの比較

| モード | 説明 |
| --- | --- |
| 読み取り専用キャッシュ | ホットな読み取りデータのみをキャッシュするため、SSD の故障や停電が元データに与えるリスクは比較的低くなります。 |
| 読み書きキャッシュ | 読み取りと書き込みの両方を高速化し、性能が向上します。SSD の故障や異常な停電により、まだ書き戻されていないデータが影響を受ける可能性があります。 |

### キャッシュの管理

| 操作 | 説明 |
| --- | --- |
| ステータスの表示 | キャッシュ名、モード、容量、ヒット率、関連するボリュームを表示します。 |
| キャッシュの削除 | キャッシュとボリュームの紐付けを解除します。読み書きキャッシュを削除する前に、システムはデータの書き戻しを保証します。その間はシャットダウンや SSD の取り外しを行わないでください。 |
| キャッシュの修復 | キャッシュが降格または破損した場合、案内に従ってすべてのキャッシュディスクを再接続し、修復を試みることができます。 |
| 既存キャッシュの割り当て | 既存のキャッシュプールの残り容量を他のボリュームの高速化に使用します。 |

<Callout title="データの安全性" type="warn">
  SSD キャッシュを作成すると、選択した SSD のデータが消去されます。読み書きキャッシュには信頼できる電源が必要です。異常な停電や SSD の故障はデータリスクを引き起こす可能性があります。SSD を取り外す前に、必ずシステム上で対応するキャッシュを削除してください。
</Callout>

## ストレージ状態の読み方

| 状態／表示 | 意味 | 推奨する対処 |
| --- | --- | --- |
| Normal | ストレージボリュームは正常に読み書きできます。 | 定期的なバックアップとハードディスクの健康検査を続けてください。 |
| Degraded | RAID の冗長性が低下していますが、通常はデータにアクセスできます。 | 直ちにデータをバックアップし、メンバーディスクを確認して、できるだけ早く修復または交換してください。 |
| Damaged/異常 | ストレージ構成またはメンバーディスクに重大な異常があります。 | 書き込みを続けず、読み取り可能なデータをバックアップしてサポートに連絡してください。 |
| Syncing/復旧中 | RAID が同期または再構築中です。 | 電源を安定に保ち、再起動、停電、ハードディスクの抜き差しを行わないでください。 |
| Formatting | フォーマット中です。 | 完了を待ち、操作を中断しないでください。 |
| Read-only | 接続、ハードディスク、ファイルシステムのリスクを検出したため、保護のために書き込みが禁止されています。 | ハードディスクと接続を確認し、データをバックアップして案内に従って修復してください。 |
| ホットスペア | ハードディスクが待機状態にあり、メンバーディスクの故障時に自動的に復旧に参加できます。 | ホットスペアの健康状態を保ち、無断で流用しないでください。 |

## 作成または変更前のチェックリスト

1. 選択したハードディスクに保持が必要なデータがないことを確認します。
2. ハードディスクの健康状態、温度、通電時間、S.M.A.R.T の結果を確認します。
3. ハードディスクの台数、インターフェース、容量が目標の RAID の要件を満たしていることを確認します。
4. 予想される利用可能容量、データ保護容量、未使用容量を理解します。
5. バックアップ、ダウンロード、同期、コンテナ、インデックス、データベースの書き込みタスクを停止します。
6. 無停電電源を準備するか、電力が不安定な時間帯を避けます。
7. 現在のストレージボリューム名、メンバーディスクの番号、マウントパスを記録します。

## RAID 選択の推奨

| 要件 | 推奨モード |
| --- | --- |
| 単一ディスクの最大容量を重視し、冗長性は不要 | Basic |
| 複数ディスクを順に連結し、後からディスクを追加 | JBOD |
| 一時的なキャッシュ、再構築可能なデータ、速度を追求 | RAID 0 |
| 2 台のディスクで重要な写真と文書を保護 | RAID 1 |
| 家庭または小規模チームで容量、性能、保護のバランスを取る | RAID 5 |
| より高い故障耐性が必要で、十分な台数のハードディスクがある | RAID 6 |
| 高性能かつミラー保護が必要 | RAID 10 |

<Callout title="容量に関する注意" type="info">
  RAID の利用可能容量は、パリティ、ミラー、ハードディスク間の容量差の影響を受けます。容量の異なるハードディスクで RAID を構成する場合、通常は小さい方の容量またはモードのルールに従って計算されます。作成ウィザードに表示される予想容量が最終的な判断基準です。
</Callout>

## ホットスペアのポリシー

- **グローバルホットスペア／プール内ホットスペア**：関連するストレージ領域のメンバーディスクが故障したときに自動的に引き継ぎ、復旧時間を短縮します。
- **適用シーン**：直ちにハードディスクを交換しにくいリモート運用、重要な業務ボリューム、ハードディスクの台数が多い RAID 6/10。
- **注意事項**：ホットスペアはバックアップではありません。同期中は性能が低下する可能性があり、元のボリュームは復旧が完了するまで降格状態のままです。

## SSD キャッシュ選択の推奨

| シーン | 推奨 |
| --- | --- |
| 主に繰り返し読み取るホットデータを高速化 | 読み取り専用キャッシュ。リスクが比較的低くなります。 |
| 書き込み応答を高速化し、UPS がある | 読み書きキャッシュを検討できます。 |
| UPS がない、またはデータが極めて重要 | 読み書きキャッシュを避け、HDD/RAID の性能向上を優先してください。 |
| 複数ユーザーが同じディレクトリに同時アクセス | 読み取り専用キャッシュの効果が比較的明確です。 |
| 小さなファイルのランダム書き込みが多い | アプリの書き込みパターンと SSD の寿命を合わせて評価する必要があります。 |

読み書きキャッシュを作成または削除するときは、システムが SSD 内の未書き戻しデータを HDD に同期する必要があります。その間はシャットダウン、再起動、SSD の取り外しを行わないでください。

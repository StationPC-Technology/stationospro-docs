存储空间页分为 **存储空间** 与 **SSD 缓存加速**。存储空间标签用于创建和管理由一块或多块硬盘组成的卷；SSD 缓存标签用于将高速 SSD 作为 HDD 卷的缓存，提高热点数据访问性能。

## 存储空间标签

![Storage](/images/common/app-guide/settings-img/storage.png)

### 存储卷列表

每个存储卷卡片显示：

| 字段 | 说明 |
| --- | --- |
| 名称 | 存储卷名称，例如 Storage volume1。 |
| 健康状态 | Normal、Degraded 等状态；异常时需要尽快检查硬盘。 |
| 存储模式/RAID | Basic、JBOD、RAID0、RAID1、RAID5、RAID6、RAID10 等。 |
| 容量 | 已使用容量 / 总容量。 |
| 硬盘类型 | HDD、SSD 等。 |
| 接口 | SATA、NVMe 等。 |
| 文件系统 | 当前卷使用的文件系统，例如 Btrfs。 |
| 使用的硬盘 | 显示组成该卷的硬盘及容量；点击硬盘可查看对应硬盘信息。 |

### 存储卷操作

存储卷卡片或更多菜单中可能提供以下操作：

| 操作 | 说明 |
| --- | --- |
| 创建存储空间 | 将空闲硬盘初始化为新存储卷。创建过程会格式化所选硬盘。 |
| 修改存储模式 | 在兼容条件下变更 RAID 类型，可能需要添加或移除硬盘。 |
| 添加硬盘 | 为支持的 RAID 卷扩容；新硬盘会被格式化。 |
| 添加/移除热备盘 | 为 RAID 卷指定备用硬盘。当成员盘故障时，热备盘可自动参与恢复。 |
| 更换硬盘 | 在故障或容量升级场景中替换成员盘。 |
| 修复/检测 | 用于异常状态排查和恢复。 |

### RAID 与存储模式

| 模式 | 硬盘要求 | 优点 | 风险/限制 |
| --- | --- | --- | --- |
| Basic | 1 块 | 充分利用单盘容量 | 无数据保护，硬盘损坏则该盘数据丢失 |
| JBOD | 至少 1 块 | 将多块硬盘串联为一个可用空间，扩容简单 | 无冗余，任意成员盘故障可能导致整个空间数据丢失 |
| RAID 0 | 至少 2 块 | 读写速度最快，容量利用率高 | 无数据保护，任意硬盘损坏会导致全部数据丢失 |
| RAID 1 | 至少 2 块 | 镜像保护，支持 n-1 块盘故障不丢数据 | 容量利用率低 |
| RAID 5 | 至少 3 块 | 兼顾性能与保护，支持单盘故障后通过校验恢复 | 写入相对较慢，恢复耗时较长 |
| RAID 6 | 至少 4 块 | 双校验，支持同时 2 块盘故障 | 写入速度与空间利用率进一步降低 |
| RAID 10 | 至少 4 块且为偶数 | 先镜像后条带，兼顾高性能与高保护 | 空间利用率约一半 |

### 文件系统选择

创建向导中可选择文件系统：

| 文件系统 | 适用性 |
| --- | --- |
| Btrfs | 支持快照、子卷与高效复制，适合需要灵活备份和版本管理的家庭用户或轻度开发者。 |
| EXT4 | 成熟稳定，适合传统文件服务、资源有限的设备或追求稳定性的办公场景。 |

### 创建存储空间流程

1. 点击 **创建存储空间**。
2. 选择空闲硬盘。系统会实时计算可用 RAID 模式和预计容量。
3. 选择存储模式/RAID，并确认可用容量、数据保护容量等信息。
4. 选择文件系统格式。
5. 选择可使用该存储空间的用户，并可设置普通用户容量限制。
6. 确认摘要与格式化警告。
7. 开始创建并等待格式化完成。

<Callout title="危险操作" type="error">
  创建、修改、扩容或更换存储卷都可能格式化所选硬盘，并删除硬盘中的所有数据。操作开始后请勿断电、重启或拔插硬盘。务必先备份重要数据。
</Callout>

## SSD 缓存加速标签

SSD 缓存将热点数据保存在高速 SSD 上，减少 HDD 读取等待时间。使用该功能前，设备中必须至少安装一块未被占用的 SSD。

![SSD Cache](/images/common/app-guide/settings-img/storage-ssd-cache.png)

### 创建 SSD 缓存

| 配置项 | 说明 |
| --- | --- |
| 加速对象 | 选择要加速的 HDD 存储卷。 |
| 缓存 SSD | 选择空闲 SSD；没有可用 SSD 时需先安装或释放硬盘。 |
| 缓存名称 | 默认可自动生成，也可按用途命名。 |
| 缓存模式 | 只读缓存或读写缓存。 |
| 缓存 RAID | 多块 SSD 时可选择缓存 RAID 模式。 |
| 缓存容量 | 可选择容量最大化或自定义容量；剩余容量可继续分配给其他卷。 |
| 风险确认 | 需要确认了解缓存创建、格式化 SSD 与读写缓存断电风险。 |

### 缓存模式对比

| 模式 | 说明 |
| --- | --- |
| 只读缓存 | 只缓存热点读取数据，SSD 故障或断电对源数据风险较低。 |
| 读写缓存 | 读取与写入均加速，性能更好；SSD 故障或异常断电可能影响尚未写回的数据。 |

### 缓存管理

| 操作 | 说明 |
| --- | --- |
| 查看状态 | 查看缓存名称、模式、容量、命中率和关联卷。 |
| 删除缓存 | 解除缓存与卷的绑定。删除读写缓存前系统会确保数据写回，期间请勿关机或移除 SSD。 |
| 修复缓存 | 缓存降级或损坏时，可按提示重新接入全部缓存盘并尝试修复。 |
| 分配已有缓存 | 使用已有缓存池的剩余容量为其他卷加速。 |

<Callout title="数据安全" type="warn">
  创建 SSD 缓存会清除所选 SSD 数据。读写缓存需配置可靠供电；异常断电或 SSD 故障可能造成数据风险。移除 SSD 前，务必先在系统中删除对应缓存。
</Callout>

## 存储状态解读

| 状态/标识 | 含义 | 建议处理 |
| --- | --- | --- |
| Normal | 存储卷可正常读写。 | 保持例行备份和硬盘健康检查。 |
| Degraded | RAID 冗余降低，但通常仍可访问数据。 | 立即备份数据，检查成员盘，尽快修复或更换硬盘。 |
| Damaged/异常 | 存储结构或成员盘严重异常。 | 避免继续写入，先备份可读数据并联系支持。 |
| Syncing/恢复中 | RAID 正在同步或重建。 | 保持供电稳定，不要重启、断电或拔插硬盘。 |
| Formatting | 正在格式化。 | 等待完成，不要中断操作。 |
| Read-only | 系统检测到连接、硬盘或文件系统风险后保护性禁写。 | 检查硬盘与连接，备份数据后按提示修复。 |
| 热备 | 硬盘待命，成员盘故障时可自动参与恢复。 | 保持热备盘健康，不要随意挪用。 |

## 创建或修改前的检查清单

1. 确认所选硬盘确实没有需要保留的数据。
2. 查看硬盘健康状态、温度、通电时间和 S.M.A.R.T 结果。
3. 确认硬盘数量、接口和容量满足目标 RAID 要求。
4. 理解预计可用容量、数据保护容量和未利用容量。
5. 停止备份、下载、同步、容器、索引和数据库写入任务。
6. 准备不间断供电或避免电力不稳定时段。
7. 记录当前存储卷名称、成员盘编号和挂载路径。

## RAID 选择建议

| 需求 | 推荐模式 |
| --- | --- |
| 单盘最大容量，不关注冗余 | Basic |
| 顺序拼接多盘、后续继续加盘 | JBOD |
| 临时缓存、可重建数据、追求速度 | RAID 0 |
| 两盘保护重要照片和文档 | RAID 1 |
| 家用或小型团队均衡容量、性能与保护 | RAID 5 |
| 更高故障容忍度，可用硬盘数充足 | RAID 6 |
| 高性能且需要镜像保护 | RAID 10 |

<Callout title="容量提醒" type="info">
  RAID 可用容量会受校验、镜像和硬盘容量差异影响。不同容量硬盘组成 RAID 时，通常按较小容量或模式规则计算。创建向导中的预计容量是最终判断依据。
</Callout>

## 热备盘策略

- **全局热备/池内热备**：当关联存储空间成员盘故障时自动接管，缩短恢复窗口。
- **适用场景**：不方便立即更换硬盘的远程部署、重要业务卷、硬盘数量较多的 RAID 6/10。
- **注意事项**：热备盘不是备份；同步期间性能可能下降，且原卷在恢复完成前仍处于降级状态。

## SSD 缓存选择建议

| 场景 | 建议 |
| --- | --- |
| 主要提升重复读取热点数据 | 只读缓存，风险较低。 |
| 需要提升写入响应，且有 UPS | 可评估读写缓存。 |
| 无 UPS 或数据极其重要 | 避免读写缓存，优先提升 HDD/RAID 性能。 |
| 多用户并发访问同一目录 | 只读缓存收益较明显。 |
| 随机写入大量小文件 | 需结合应用写入模式和 SSD 寿命评估。 |

创建或删除读写缓存时，系统可能需要将 SSD 中未写回的数据同步到 HDD。期间不要关机、重启或移除 SSD。

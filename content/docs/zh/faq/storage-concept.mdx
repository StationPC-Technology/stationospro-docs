在 StationOS Pro 中，**硬盘**与**存储空间**是构建数据存储的两个核心概念。简单来说，硬盘是数据的物理载体，存储空间是你实际存放和管理文件的逻辑区域。理解两者之间的关系，是合理规划容量、保障数据安全、发挥设备性能的基础。

## 硬盘：数据的物理载体

硬盘是实际存储数据的物理设备。StationPC 设备同时支持机械硬盘（HDD）与固态硬盘（SSD）：

- **HDD（机械硬盘）**：容量大、单位容量价格低，适合照片、影片、下载资料等海量数据的长期存储。
- **SSD（固态硬盘）**：读写速度快，适合承载 Docker 容器、虚拟机等对性能要求较高的场景，也可作为 HDD 存储空间的缓存加速。

硬盘型号与容量的选择请参考[硬盘兼容性列表](../compatible/support-hdd)。

## 存储空间：实际使用数据的逻辑区域

存储空间是用户实际存放和管理数据的逻辑区域，相当于一块独立的"虚拟硬盘"。系统通过 RAID 技术把一块或多块硬盘组织成存储空间，但在界面上只需要一步操作：**直接创建存储空间**，无需先单独创建存储池。

创建存储空间时，向导会引导你完成以下选择：

1. **选择硬盘**：从内置硬盘或外接存储中挑选参与组建的硬盘。
2. **选择存储模式**：即 RAID 模式，决定容量的利用方式与数据保护等级。
3. **选择文件系统**：Btrfs 或 EXT4。
4. **设置使用权限**：选择可使用该存储空间的用户，并可限制普通用户的可用容量。
5. **确认并创建**：确认摘要与格式化警告后开始创建。

创建完成后，存储空间卡片会展示健康状态、存储模式、已用容量、文件系统、成员硬盘与热备盘等信息，便于随时掌握存储状况。

## 存储模式：容量与安全的平衡点

存储模式（RAID）决定了多块硬盘如何协同工作。不同模式在容量利用率与数据安全之间侧重不同：

- **Basic**：单盘独立使用，容量利用率最高，但没有数据保护。
- **JBOD**（界面中显示为 Linear）：将多块硬盘容量线性拼接为一个空间，扩容简单但无冗余。
- **RAID 0**：数据分块存储在多块硬盘上，读写速度快，但任意一块硬盘损坏会导致全部数据丢失。
- **RAID 1**：数据在成员盘之间镜像保存，允许部分硬盘故障而不丢失数据。
- **RAID 5 / RAID 6**：通过校验提供容错，兼顾容量利用率与安全，适合盘位较多的设备。
- **RAID 10**：先镜像后条带，兼顾高性能与高保护，空间利用率约为总容量的一半。

各模式的硬盘数量要求、容量计算方式与详细对比，请参考[存储空间设置](../app-guide/settings/storage)。

此外，还可以为 RAID 存储空间指定**热备盘**：当成员盘故障时，热备盘会自动顶替参与重建，缩短数据处于降级状态的时间窗口。

## 硬盘与存储空间的关系小结

一句话概括：**硬盘提供物理容量，存储模式决定组织方式，存储空间是最终呈现给你的可用区域。**

- **硬盘 → 存储空间**：创建存储空间时选定的硬盘，按存储模式组合成一个整体。模式决定了实际可用容量与容错能力。
- **存储空间 → 用户数据**：在存储空间中创建共享文件夹、上传文件、设置访问权限后，即可通过[文件管理](../app-guide/files)应用或 SMB、WebDAV 等协议在各类设备上访问数据。

## 与其他 NAS 系统的差异：为什么没有"存储池"？

不少 NAS 系统采用「硬盘 → 存储池 → 存储空间」的三层结构：先把硬盘组合成存储池，再在池上划分出多个存储空间。

StationOS Pro 将这两步合并为一步：创建存储空间时选好硬盘与存储模式，系统自动完成底层的池化。这样的取舍是：

- **好处**：流程更简单直观，不需要先理解"存储池"的概念，就能正确组建存储。
- **局限**：一组硬盘只能对应一个存储空间，无法在同一组硬盘上再划分出多个空间。如果需要多个相互独立的空间，请使用不同的硬盘分别创建。

## 存储规划建议

| 需求 | 建议 |
| --- | --- |
| 照片、文档等重要数据 | RAID 1 及以上冗余模式，并保持定期备份 |
| Docker、虚拟机等高性能场景 | 使用 SSD 组建存储空间，或开启 SSD 缓存加速 |
| 影片、下载等大容量数据 | 大容量 HDD 搭配 JBOD 或 RAID 5 |
| 多人协作 | 分别创建存储空间，或通过文件夹权限隔离不同成员的数据 |

<Callout title="提示" type="idea">
RAID 提供的是硬盘故障容错，不能代替备份。重要数据仍建议遵循"3-2-1"备份原则：至少保留 3 份数据、存放在 2 种介质上，其中 1 份异地保存。
</Callout>

네트워크 설정 페이지는 **일반**과 **네트워크 연결**로 나뉩니다. 일반 페이지는 전역 게이트웨이, DNS 및 고급 확인 정책을 담당하고, 네트워크 연결 페이지는 각 네트워크 카드의 IP 매개변수, 브리지 및 링크 집계를 담당합니다.

## 일반

![Network General](/images/ko/app-guide/settings-img/network-general.png)

### 기본 게이트웨이

| 필드 | 설명 |
| --- | --- |
| 기본 게이트웨이 | 현재 IPv4 기본 게이트웨이입니다. 예: `172.16.0.1`. 기기가 다른 네트워크 대역이나 인터넷에 접근할 때 우선 사용됩니다. |
| IPv6 기본 게이트웨이 | 현재 IPv6 기본 게이트웨이입니다. 구성되지 않았거나 사용할 수 없으면 `-`로 표시됩니다. |

### DNS 서버

| 옵션 | 설명 |
| --- | --- |
| DNS 서버 수동 구성 | 선택하지 않으면 DHCP 등으로 DNS를 자동으로 가져오며, 선택하면 직접 입력할 수 있습니다. |
| 기본 DNS 서버 | 필수입니다. 도메인 확인의 우선 서버입니다. 예: `202.96.134.33`. |
| 보조 DNS 서버 | 선택 사항입니다. 기본 DNS를 사용할 수 없을 때 사용합니다. 예: `202.96.128.86`. |

### 고급 설정

| 옵션 | 설명 |
| --- | --- |
| 다중 게이트웨이 사용 | 시스템이 여러 게이트웨이를 사용하도록 허용합니다. 기기가 여러 네트워크 대역 또는 여러 업링크에 연결된 시나리오에 적합합니다. |
| DNS 확인 시 IPv4 우선 사용 | 도메인에 IPv4/IPv6 레코드가 모두 있을 때 IPv4를 우선 선택하여 일부 IPv6 네트워크 불통으로 인한 접근 지연을 방지합니다. |
| IP 충돌 감지 사용 | LAN 내 주소 충돌을 감지하여 고정 IP가 다른 기기와 충돌하는 문제를 발견하는 데 도움을 줍니다. |
| 적용 | 클릭하면 현재 페이지의 수정 사항을 저장합니다. 수정 사항이 없으면 버튼을 사용할 수 없습니다. |

<Callout title="주의" type="warn">
  현재 브라우저가 네트워크를 통해 기기에 접근하는 경우 게이트웨이, DNS 또는 네트워크 카드 IP를 수정하면 연결이 끊길 수 있습니다. 새 매개변수가 라우팅 가능한지 확인하고 새 IP 또는 콘솔을 통해 연결을 복구할 준비를 하십시오.
</Callout>

## 네트워크 연결

![Network Connections](/images/ko/app-guide/settings-img/network-connections.png)

### 네트워크 카드 목록

각 네트워크 카드에는 다음이 표시됩니다:

| 필드 | 설명 |
| --- | --- |
| 인터페이스 이름 | 예: Port 1 (`enP2p33s0`), Port 2 (`enP4p65s0`). |
| 속도 | 현재 협상 속도입니다. 예: 1Gbps. |
| 듀플렉스 모드 | 전이중 또는 반이중. |
| MTU | 현재 최대 전송 단위입니다. 예: MTU1500. |
| 연결 상태 | 연결됨, 연결 안 됨, 사용 불가 등. |
| MAC 주소 | 네트워크 카드 하드웨어 주소입니다. |
| IPv4 주소/서브넷 마스크/게이트웨이 | IPv4 연결 매개변수이며 주소 옆에서 복사할 수 있습니다. |
| DNS | IPv4 DNS 서버 목록입니다. |
| IPv6 주소/게이트웨이/DNS | IPv6 연결 매개변수입니다. 구성되지 않으면 `-`로 표시됩니다. |
| 네트워크 유형 | 이더넷, 브리지, 링크 집계 등. |

### 네트워크 카드 편집

네트워크 카드의 편집 버튼을 클릭하면 다음을 수정할 수 있습니다:

| 설정 | 모드 | 필드 및 규칙 |
| --- | --- | --- |
| IPv4 | 자동 | DHCP로 주소, 마스크, 게이트웨이 및 DNS를 자동으로 가져오며 수동 입력란이 비활성화됩니다. |
| IPv4 | 수동 | IPv4 주소와 서브넷 마스크는 필수이며 게이트웨이, 기본 DNS, 보조 DNS를 입력할 수 있습니다. 주소는 유효한 IPv4 형식이어야 하고 서브넷 마스크는 연속 마스크여야 합니다. |
| MTU | 자동 | 시스템 기본 MTU를 사용합니다. |
| MTU | 수동 | 1280~9000을 입력할 수 있습니다. 수정 전에 스위치와 링크가 해당 프레임 크기를 지원하는지 확인하십시오. |

### 브리지 생성

**Create Bridge**는 두 개 이상의 물리 네트워크 카드를 동일한 브리지 네트워크에 추가할 수 있습니다:

1. **Create Bridge**를 클릭합니다.
2. 사용 가능한 물리 네트워크 카드를 최소 두 개 선택합니다.
3. 확인하면 시스템이 브리지 인터페이스를 생성합니다.
4. 생성 후 일반 인터페이스처럼 IP 매개변수를 편집할 수 있습니다.

<Callout title="팁" type="info">
  브리지는 가상 머신, 컨테이너 또는 격리된 네트워크가 물리 LAN에 직접 연결되도록 하는 데 자주 사용됩니다. 브리지를 생성하면 기존 네트워크 카드의 연결 방식이 변경될 수 있으므로 현재 관리 네트워크 카드를 잘못 선택하지 않도록 주의하십시오.
</Callout>

### 링크 집계 생성

**Create Link Aggregation**은 여러 네트워크 카드를 하나의 논리 인터페이스로 결합하여 대역폭 집계 또는 링크 백업을 구현합니다. 시스템은 동일 사양의 네트워크 카드를 사용할 것을 요구합니다.

| 분류 | 모드 | 특징 및 요구 사항 |
| --- | --- | --- |
| 스위치 구성 불필요 | Adaptive Load Balancing – bond6 | 권장됩니다. 시스템이 여러 네트워크 포트에 트래픽을 자동으로 분산하며 스위치의 집계 지원이 필요하지 않습니다. |
| 스위치 구성 불필요 | Active/Backup – bond1 | 주/백업 모드입니다. 백업 포트는 평소 비활성 상태이며 주 포트 장애 시 자동으로 전환됩니다. 신뢰성이 높지만 대역폭이 집계되지 않습니다. |
| 스위치 구성 필요 | Round Robin – bond0 | 트래픽을 라운드 로빈으로 분산하고 두 포트가 동시에 전송하여 속도를 크게 높일 수 있습니다. 스위치가 정적 집계를 지원하고 올바르게 구성되어야 합니다. |
| 스위치 구성 필요 | Balance XOR – bond2 | 해시 기반으로 링크를 분배합니다. 스위치가 정적 집계를 지원해야 하며 다중 스위치 시나리오에서는 스택 구성과 올바른 설정이 필요합니다. |
| 스위치 구성 필요 | Dynamic Link Aggregation – bond4 | IEEE 802.3ad 동적 집계입니다. 스위치가 LACP를 지원하고 올바르게 구성되어야 하며 다중 스위치에서는 스택이 필요합니다. |

### 네트워크 모드 해제

브리지 또는 링크 집계 인터페이스의 경우 더 보기 작업에서 네트워크 모드를 해제할 수 있습니다. 시스템은 해당 작업이 논리 인터페이스에 영향을 준다고 안내하며, 확인하면 구성원 네트워크 카드가 복원됩니다.

<Callout title="작업 권장 사항" type="warn">
  링크 집계 모드는 스위치 구성과 일치해야 합니다. 스위치 지원이 필요한 모드를 선택했지만 스위치가 구성되지 않으면 네트워크가 끊기거나 집계 포트가 반복적으로 비정상 상태가 될 수 있습니다.
</Callout>

## 네트워크 수정 전 준비

1. 현재 IP, 마스크, 게이트웨이, DNS, MTU 및 인터페이스 이름을 기록합니다.
2. LAN, 콘솔 또는 두 번째 네트워크 포트를 통한 복구 경로가 있는지 확인합니다.
3. 스위치 VLAN, 포트 속도, 집계 및 방화벽 정책을 확인합니다.
4. 새 고정 IP가 다른 기기와 충돌하지 않는지 확인합니다.
5. 링크 집계를 사용하는 경우 스위치 측에서 해당 구성을 먼저 완료하고 모드를 확인합니다.
6. 여러 네트워크 조건을 동시에 수정하지 말고, 매번 수정 후 연결을 먼저 검증합니다.

## 인터페이스 상태 해석

| 상태/필드 | 의미 |
| --- | --- |
| Connected | 링크가 설정되었고 주소를 가져올 수 있습니다. |
| Disconnected | 네트워크 케이블/링크가 설정되지 않았습니다. |
| 1Gbps / 2.5Gbps / 10Gbps | 현재 협상 속도이며 양쪽 기기와 케이블의 제약을 받습니다. |
| Full Duplex | 동시 송수신이 가능하며 반이중은 효율이 낮습니다. |
| MTU1500 | 표준 이더넷 MTU이며 점보 MTU는 전체 링크의 지원이 필요합니다. |
| `-` | 값을 가져오지 못했거나 해당 프로토콜 스택이 구성되지 않았습니다. |
| Bridge | 여러 물리 인터페이스로 구성된 브리지입니다. |
| Bond | 여러 네트워크 카드로 구성된 링크 집계 논리 인터페이스입니다. |

## 브리지와 링크 집계 선택

| 요구 사항 | 선택 |
| --- | --- |
| 가상 머신/컨테이너를 물리 LAN에 직접 연결 | 브리지. |
| 두 네트워크 카드 대역폭 집계, 스위치 구성 불필요 | bond6. |
| 주/백업 재해 대응, 전환 우선 | bond1. |
| 스위치에 정적 집계 구성 완료, 동시 처리량 추구 | bond0 또는 bond2. |
| 스위치가 LACP 지원, 표준 동적 집계 필요 | bond4. |
| NAS의 IP/DNS만 수정 | 일반 인터페이스 편집, 브리지 또는 집계를 생성하지 마십시오. |

## 연결 복구의 일반적인 방법

- 수정하지 않은 다른 네트워크 포트의 IP로 접근합니다.
- 컴퓨터를 동일 VLAN/동일 네트워크 대역에 연결한 후 기기를 다시 검색합니다.
- 라우터의 DHCP 임대 목록에서 새 주소를 찾습니다.
- DNS만 이상이 있는 경우 임시로 IP로 직접 접근합니다.
- 집계 포트가 연결되지 않으면 구성원 포트를 분리한 후 단일 포트로 구성을 복구합니다.
- 네트워크 구성 오류가 심한 경우 업데이트 및 복원에서 네트워크 초기화를 검토할 수 있습니다.

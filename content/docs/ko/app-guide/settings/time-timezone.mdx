시간 및 시간대 페이지는 기기 시간을 정확하게 유지하는 데 사용됩니다. 정확한 시간은 로그 정렬, 예약 작업, 인증서 검증, 2단계 인증 및 HTTPS 통신에 매우 중요합니다.

![Time](/images/ko/app-guide/settings-img/time.png)

## 시간대

| 옵션 | 설명 |
| --- | --- |
| Timezone | 기기가 위치한 시간대를 선택합니다. 예: `(UTC+08:00) Beijing, Chongqing, Hong Kong, Urumqi`. |
| 검색/필터 | 시간대 드롭다운에서 도시 또는 UTC 오프셋을 검색하여 대상 시간대를 빠르게 찾을 수 있습니다. |

기기 배포 지역과 사용자 소재지가 다른 경우 기기의 실제 위치에 따라 시간대를 설정하여 작업 실행 시간이 현지 예상과 어긋나지 않도록 하는 것이 좋습니다.

## 시간

### 자동 동기화

| 옵션 | 설명 |
| --- | --- |
| Auto Sync | NTP 서버가 정기적으로 시스템 시간을 교정합니다. 일상적인 사용에 권장합니다. |
| NTP 서버 | `pool.ntp.org`, `time.google.com`, `time.cloudflare.com`, `time.apple.com`, `time.windows.com`, `time.nist.gov`, `ntp.tencent.com`, `ntp.aliyun.com` 등을 선택할 수 있으며 사용자 지정 NTP 주소를 입력할 수도 있습니다. |
| 현재 시간 | 페이지에 현재 시스템 시간이 실시간으로 표시됩니다. |

<Callout title="팁" type="info">
  기기에서 선택한 NTP 서버에 접근할 수 없는 경우 DNS, 방화벽 아웃바운드 규칙 및 UDP 123 포트를 확인하십시오. 중국 본토 네트워크 환경에서는 NTP 서비스 제공업체가 제공하는 주소를 우선 시도할 수 있습니다.
</Callout>

### 수동 설정

| 옵션 | 설명 |
| --- | --- |
| Manual Set | 날짜와 시간을 수동으로 지정합니다. |
| Date | 날짜를 선택하며 형식은 `2026-10-14`와 같습니다. |
| Time | 시간을 입력하며 형식은 `17:46:26`과 같습니다. |
| 경고 안내 | 시스템이 시간을 정확하게 유지하도록 알리며, 편차가 너무 크면 네트워크 요청 실패 또는 서비스 이상이 발생할 수 있습니다. |

수동 설정은 격리된 네트워크 또는 NTP에 접근할 수 없는 환경에 적합합니다. 설정을 완료한 후 **적용**을 클릭하여 저장합니다.

<Callout title="주의" type="warn">
  시간을 인증서 유효 기간을 벗어나게 설정하거나 실제 시간과 크게 다르게 설정하지 마십시오. 그렇지 않으면 HTTPS, 원격 액세스, 업데이트 확인 및 2단계 인증이 실패할 수 있습니다.
</Callout>

## NTP와 수동 설정 선택

| 시나리오 | 권장 |
| --- | --- |
| 인터넷 접근 가능 | 자동 동기화. |
| 격리된 내부 네트워크 | 수동 설정 또는 내부 NTP 서버 연결. |
| 시간 편차로 인한 인증서 실패 | 먼저 사용 가능한 NTP로 전환하고 시간이 인증서 유효 범위로 돌아왔는지 확인합니다. |
| 예약 작업 실행 편차 | 시간대와 NTP를 확인하고 시간만 변경하지 마십시오. |
| 시간대가 다른 팀 | 기기의 실제 위치 시간대로 설정하여 로그 시간을 일관되게 유지합니다. |

## 시간 이상의 영향

| 기능 | 가능한 영향 |
| --- | --- |
| HTTPS/인증서 | 인증서가 아직 유효하지 않거나 만료되어 검증에 실패합니다. |
| 2단계 인증/OTP | 동적 코드의 시간 창이 일치하지 않습니다. |
| 로그 감사 | 이벤트 순서와 발생 시간을 신뢰할 수 없습니다. |
| 예약 작업 | 전원 켜기/끄기, 백업 작업이 앞당겨지거나 지연됩니다. |
| 클라우드 동기화/API | 요청 서명 또는 토큰 검증에 실패합니다. |
| 업데이트 확인 | 업데이트 소스가 요청을 거부할 수 있습니다. |

## 문제 해결 권장 사항

1. 먼저 시간대를 확인한 후 시간을 확인합니다. 두 오류가 겹치면 판단하기 어려워집니다.
2. NTP가 적용되지 않을 때 DNS와 UDP 123 아웃바운드를 테스트합니다.
3. NTP 서비스 제공업체를 변경한 후 한 번의 동기화 주기를 기다립니다.
4. 수동 설정 후 즉시 적용하고 임시 시간에 오래 머무르지 않습니다.
5. 시간을 수정한 후 클라이언트에 다시 로그인하여 세션과 캐시를 새로 고칩니다.

보안 페이지는 **포트 설정**, **계정 보안**, **보호**, **방화벽**, **인증서**, **기기 분석** 여섯 개 탭을 포함하며, 시스템 진입점을 강화하고 접근 출처를 제어하며 전송을 암호화하고 개인정보 관련 스위치를 확인하는 데 사용됩니다.

## 포트 설정

![Port Settings](/images/ko/app-guide/settings-img/security-port-settings.png)

### 현재 정보

페이지는 현재 웹 관리 진입점 포트를 표시합니다:

| 필드 | 기본값 | 설명 |
| --- | --- | --- |
| HTTP 포트 | 9500 | HTTP로 관리 콘솔에 접근합니다. |
| HTTPS 포트 | 9501 | HTTPS로 관리 콘솔에 접근합니다. |

### 포트 설정 팝업

| 옵션 | 설명 |
| --- | --- |
| HTTP 포트 번호 | 필수이며 범위는 1~65535이고 HTTPS 포트와 같을 수 없습니다. |
| HTTPS 포트 번호 | 필수이며 범위는 1~65535입니다. HTTPS 강제 또는 기본 포트 리디렉션을 켤 때는 0일 수 없습니다. |
| HTTPS 연결 강제 | HTTP 연결을 HTTPS 연결로 리디렉션합니다. |
| 80 및 443 포트 리디렉션 | 80을 HTTP 포트로, 443을 HTTPS 포트로 리디렉션합니다. 활성화하면 기기 접근 시 포트 번호를 입력하지 않아도 됩니다. |

<Callout title="주의" type="warn">
  기본 포트 리디렉션을 활성화할 때 HTTP/HTTPS 포트는 80 또는 443을 사용할 수 없습니다. 포트 수정 후 새 포트로 관리 콘솔을 다시 열고 방화벽 또는 라우터 포워딩 규칙이 함께 업데이트되었는지 확인하십시오.
</Callout>

## 계정 보안

계정 보안 페이지는 시스템 수준의 2단계 인증 정책을 제어합니다.

![Account Security](/images/ko/app-guide/settings-img/security-account-security.png)

| 옵션 | 설명 |
| --- | --- |
| 2단계 인증 강제 사용 | 켜면 정책 대상 사용자가 로그인할 때 두 번째 단계 OTP 인증을 완료해야 합니다. |
| 모든 사용자 | 정책을 모든 사용자에게 적용합니다. |
| 관리자만 | 관리자 계정에만 2단계 인증을 강제합니다. |
| 지정 사용자 | 선택한 사용자 또는 사용자 그룹에만 2단계 인증을 강제합니다. |
| 지정 사용자 편집 | 사용자/사용자 그룹 선택기에서 정책 대상을 추가하거나 제거합니다. |

<Callout title="전제 조건" type="info">
  2단계 인증은 이메일 알림 서비스에 의존합니다. 켜기 전에 '시스템 설정 → 알림 설정'에서 발신 이메일을 구성하십시오. 이메일 서비스를 끄면 2단계 인증 인증 코드를 보내지 못할 수 있습니다.
</Callout>

## 보호

보호 페이지는 비정상 로그인 IP를 자동으로 차단하고 허용 목록과 차단 목록을 유지 관리하는 데 사용됩니다.

![Protection](/images/ko/app-guide/settings-img/security-protection.png)

### 비정상 IP 차단

| 옵션 | 설명 |
| --- | --- |
| 서비스 스위치 | 켜면 시스템이 규칙에 따라 비정상 IP 로그인을 차단합니다. |
| 규칙 편집 | 자동 차단 임계값, 집계 시간 및 차단 해제 시간을 구성합니다. |

### 자동 차단 규칙

| 필드 | 기본값 | 범위 | 설명 |
| --- | --- | --- | --- |
| 로그인 시도 횟수 | 10회 | 1~100 | 차단을 실행하는 데 필요한 실패 횟수입니다. |
| 설정 시간 내 | 5분 | 1~10080분 | 실패 횟수를 집계하는 시간 창입니다. |
| 자동 차단 해제 규칙 | 1시간 | 30분/1시간/1일/7일/30일/영구 | 차단된 IP의 차단 해제 시간입니다. |

### 허용 목록 및 차단 목록

| 목록 | 우선순위 및 역할 |
| --- | --- |
| 허용 목록 | 목록 내 IP/CIDR는 항상 연결과 로그인이 허용되며 차단 규칙의 영향을 받지 않고 차단 목록보다 우선순위가 높습니다. |
| 차단 목록 | 목록 내 IP/CIDR는 항상 연결과 로그인이 제한됩니다. |

목록 표에는 클라이언트 IP, 최근 접근 시간, 만료 시간(차단 목록), 영구 표시 및 비고가 표시됩니다. 다음을 지원합니다:

| 작업 | 설명 |
| --- | --- |
| 추가 | 하나 이상의 IP/CIDR를 입력하며 여러 주소는 줄바꿈 또는 쉼표로 구분합니다. 차단 목록은 차단 해제 시간을 선택할 수 있습니다. |
| 비고 | 최대 180자이며 출처나 용도를 표시하는 데 사용합니다. |
| 삭제 | 하나 이상의 레코드를 선택한 후 삭제하여 해당 제한을 해제합니다. |

## 방화벽

방화벽 페이지는 인바운드 및 아웃바운드 규칙에 따라 네트워크 트래픽을 제어합니다.

![Firewall](/images/ko/app-guide/settings-img/security-firewall.png)

### 기본 설정

| 옵션 | 설명 |
| --- | --- |
| 방화벽 스위치 | 켜면 시스템이 인바운드/아웃바운드 규칙에 따라 트래픽을 제어합니다. |
| 고급 설정 | 작업 모드와 LAN 기본 허용을 구성합니다. |

### 고급 설정

| 옵션 | 설명 |
| --- | --- |
| 작업 모드 | Auto는 XDP native 모드를 우선 선택하고 Generic은 기존 커널 네트워크 스택을 사용합니다. 호환성 문제가 발생하면 전환할 수 있습니다. |
| LAN | '기본 허용'을 켜면 LAN 트래픽이 기본적으로 허용되어 관리 콘솔이 잘못 차단될 확률을 낮춥니다. |

### 인바운드 규칙 및 아웃바운드 규칙

| 필드 | 설명 |
| --- | --- |
| 네트워크 연결 | 모든 인터페이스 또는 지정 네트워크 인터페이스. |
| 포트 | 단일 포트, 쉼표로 구분된 포트 또는 범위. 예: `80`, `443`, `1-65535`. |
| 프로토콜 | 전체, TCP, UDP, ICMP. |
| 소스 IP/대상 IP | 사용자 지정 IP 또는 CIDR. 인바운드는 소스 IP, 아웃바운드는 대상 IP를 확인합니다. |
| 권한 | 허용 또는 거부. |
| 상태 | 적용 또는 비활성화. |
| 비고 | 규칙 용도 설명. |
| 순서 | 규칙을 끌어서 정렬할 수 있으며 앞에 있을수록 우선순위가 높습니다. |
| 아래 규칙에 모두 해당하지 않는 경우 | 기본 허용 또는 기본 거부를 설정합니다. |

<Callout title="위험 작업" type="error">
  잘못된 방화벽 규칙은 관리 콘솔, 원격 액세스 또는 앱 서비스에 접근할 수 없게 만들 수 있습니다. 구성 전에 현재 관리 연결을 유지하고 관리 포트, SSH 포트 및 LAN을 우선 허용하는 것이 좋습니다.
</Callout>

## 인증서

인증서 페이지는 시스템 HTTPS, FTPS, WebDAV 및 원격 액세스에 사용되는 인증서를 관리합니다.

![Certificate](/images/ko/app-guide/settings-img/security-certificate.png)

### 인증서 목록

| 필드 | 설명 |
| --- | --- |
| 인증서 이름 | 사용자가 식별할 수 있는 이름입니다. |
| 인증서 유형 | 시스템 자체 서명 인증서, Let's Encrypt 인증서 또는 가져온 인증서. |
| 발급 기관 | 인증서 발급자입니다. |
| 대체 도메인 | 인증서가 포함하는 다른 도메인이며 없으면 `-`로 표시됩니다. |
| 유효 기간 | 만료 시간입니다. |
| 자동 갱신 | 시스템 인증서 또는 Let's Encrypt 인증서는 만료 전에 자동 갱신할 수 있습니다. |
| 상태 | 유효, 곧 만료, 만료됨. |
| 작업 | 상세 정보 보기/편집, 업데이트, 다운로드, 삭제. 삭제 후에는 복구할 수 없습니다. |

### 인증서 추가

| 방식 | 설명 |
| --- | --- |
| 인증서 가져오기 | 로컬에서 업로드하거나 NAS에서 인증서 파일, 개인 키 파일 및 선택적 중간 인증서를 선택합니다. 이미 CA 발급 인증서가 있는 사용자에게 적합합니다. |
| 인증서 발급 | Let's Encrypt에서 무료 인증서를 가져오고 자동 갱신합니다. 이메일을 입력하고 DDNS 도메인 또는 사용자 지정 도메인과 제공업체를 선택해야 합니다. |

### Let's Encrypt 인증서 발급 주의 사항

- 무료 인증서에는 신청 빈도와 수량 제한이 있습니다.
- HTTP 검증은 80 포트를 NAS로 포워딩해야 하며, DNS 검증은 제공업체의 지원이 필요합니다.
- 도메인은 현재 공인 IP를 올바르게 가리켜야 합니다.
- 발급 성공 후 시스템은 인증서 만료 전에 자동으로 갱신합니다.

### 서비스 구성

**Service Config**는 FTPS, WebDAV 및 원격 액세스 인증서에 사용할 인증서를 선택하는 데 사용됩니다. 확인하면 관련 서비스가 선택한 인증서로 암호화 연결을 설정합니다.

## 기기 분석

기기 분석 페이지는 두 개의 개인정보 관련 스위치를 포함합니다.

![Device Analytics](/images/ko/app-guide/settings-img/security-device-analytics.png)

| 옵션 | 설명 |
| --- | --- |
| 기기 분석 개선 프로그램 참여 | 시스템이 일부 익명 사용 데이터를 수집하여 제품 사용 분석, 안정성 향상 및 기능 개선에 사용합니다. 언제든지 탈퇴할 수 있습니다. |
| webfind 서비스 활성화 | 켜면 LAN에서 Station OS 기기를 발견할 수 있습니다. 시스템은 이 서비스를 제공하기 위해 IP 주소와 포트 정보를 수집합니다. |

두 설명 모두 개인정보 처리방침으로 연결됩니다. 데이터 수집에 참여하지 않거나 LAN 검색 기능을 제공하지 않으려면 해당 스위치를 끄면 됩니다.

<Callout title="보안 기준 권장 사항" type="info">
  HTTPS/HTTPS 강제, 2단계 인증, 비정상 IP 보호 및 방화벽을 활성화하고, 필요한 포트만 열며, 인증서 자동 갱신을 구성하고, 외부 접근은 Station ID 또는 VPN을 우선 사용하는 것이 좋습니다.
</Callout>

## 포트 정책 권장 사항

| 시나리오 | 권장 사항 |
| --- | --- |
| 가정 LAN | HTTP/HTTPS를 유지할 수 있으며 신뢰할 수 있는 기기에만 로그인 상태를 저장합니다. |
| 공용 인터넷 또는 공유 네트워크 | HTTPS/HTTPS 강제를 활성화하여 일반 텍스트로 비밀번호를 제출하지 않도록 합니다. |
| 포트만 생략하려는 경우 | 80/443 리디렉션을 활성화하되 라우터와 방화벽 규칙이 함께 적용되는지 확인합니다. |
| 기본 포트 변경 | 1024–65535 중 사용되지 않는 포트를 선택하고 SMB/FTP/SSH와 충돌하지 않도록 합니다. |
| 원격 액세스 | Station ID 또는 VPN을 우선 사용하고 관리 포트를 직접 노출하지 마십시오. |

## 2단계 인증 정책 비교

| 범위 | 장점 | 적용 |
| --- | --- | --- |
| 모든 사용자 | 보안 기준이 가장 높습니다. | 민감한 파일이 있거나 여러 사람이 사용하는 기기. |
| 관리자만 | 보안과 일반 사용자 편의성을 함께 고려합니다. | 가정 기기 또는 일반 계정 권한이 낮은 경우. |
| 지정 사용자 | 고위험 계정을 정밀하게 관리합니다. | 백업, 재무, 운영 등 특수 계정에만 적용. |

정책을 켜면 지정 범위의 사용자는 개인 설정에서 인증 앱 또는 이메일 인증 구성을 완료해야 하며, 관리자는 이메일 서비스가 사용 가능한지 먼저 확인해야 합니다.

## IP 보호 설계 권장 사항

- **허용 목록**: 고정 사무실 네트워크, 가정 출구, VPN 출구, 배스천 호스트 주소.
- **차단 목록**: 반복 로그인 시도 출처, 침해된 네트워크 대역, 명확한 스캔 출처.
- **임계값**: 가정 기기는 비교적 엄격하게 설정할 수 있으며, 여러 사람이 사용하거나 프록시 출구 환경에서는 임계값을 너무 작게 설정하지 마십시오.
- **차단 해제 시간**: 중요 기기는 길게 설정할 수 있고, 임시 네트워크는 복구가 쉽도록 짧게 선택할 수 있습니다.
- **VPN 알림**: 출구 IP 변경은 감지 결과에 영향을 주므로 필요하면 고정 출구 또는 사용자 지정 감지 주소를 사용하십시오.

## 방화벽 규칙 설계 절차

1. 관리 포트, SSH 포트 및 LAN 네트워크 대역을 먼저 허용합니다.
2. HTTPS, WebDAV, FTPS 등 인바운드 서비스와 포트를 명확히 합니다.
3. 소스 IP, 프로토콜 및 포트별로 최소 범위 규칙을 생성합니다.
4. 거부 규칙으로 명확히 필요 없는 출처를 차단합니다.
5. 끌어서 우선순위를 조정하며 앞에 있을수록 먼저 일치합니다.
6. 기본 정책을 설정하며 방화벽에 익숙하지 않으면 먼저 허용을 유지하고 규칙 검증 후 강화하십시오.
7. 새 규칙이 신뢰할 수 있음을 확인할 때까지 연결된 관리 세션을 하나 유지합니다.

## 인증서 문제 해결

| 문제 | 확인 |
| --- | --- |

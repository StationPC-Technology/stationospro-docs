AI 모델 페이지는 **기본 기능**, **모델 관리**, **저장 위치** 세 탭으로 나뉩니다. 이곳에서 전체 검색과 Station AI가 사용하는 로컬 인식 기능, 대규모 언어 모델 파일, 그리고 모델 및 인덱스 데이터의 저장 위치를 제어합니다.

## 기본 기능

기본 기능 페이지는 전체 검색과 콘텐츠 인식에 필요한 AI 기능 모듈을 관리합니다.

![AI Basic Capabilities](/images/ko/app-guide/settings-img/ai-models.png)

### 기능 모듈

| 기능 | 역할 | 비활성화 영향 |
| --- | --- | --- |
| 얼굴 인식 | 인물을 인식하고 그룹화하며 얼굴 검색과 스마트 앨범을 지원합니다. | 얼굴 검색, 인물 그룹화 등의 기능을 사용할 수 없습니다. |
| 문자 인식 | 이미지 속 문자를 인식하여 키워드로 이미지 내용을 찾을 수 있습니다. | 이미지 OCR 및 이미지 문자 검색 기능이 제한됩니다. |
| 파일 인식 | 파일 이름, 경로, 문서 내용 및 의미를 인덱싱하여 전체 검색 효과를 높입니다. | 문서 내용 및 의미 검색 기능이 제한됩니다. |
| 시각 콘텐츠 인식 | 이미지/동영상의 장면과 객체를 인식하여 콘텐츠 매칭 검색에 사용합니다. | 이미지로 이미지 검색, 장면/객체 검색 기능이 제한됩니다. |

### 상태 및 인덱스 정보

문자 인식, 파일 인식, 시각 콘텐츠 인식 등의 모듈에는 다음이 표시됩니다:

| 필드 | 설명 |
| --- | --- |
| 인식된 파일 | 인덱싱이 완료된 파일 수. |
| 인덱스 실패 | 인덱스를 구축할 수 없는 파일 수. 파일 손상, 지원되지 않는 형식, 권한 이상 또는 스토리지 일시 사용 불가 등이 원인일 수 있습니다. |
| 최근 인덱싱 시간 | 최근 인덱싱이 완료된 시간. |
| 기능 상태 | 정상, 비활성화됨, 설치 중, 업데이트 중, 재구축 중, 마이그레이션 중, 이상, 공간 부족 일시 중지 등. |
| 유지 관리 작업 | 기능별로 설치, 업데이트, 활성화/비활성화, 복구 또는 인덱스 재구축을 수행할 수 있습니다. |

<Callout title="팁" type="info">
  기능을 처음 켜면 인덱스를 구축해야 하며, 소요 시간은 파일 수, 문서 유형 및 스토리지 성능에 따라 달라집니다. 인덱싱 중에도 기기를 계속 사용할 수 있지만 검색 결과가 완전하지 않을 수 있습니다.
</Callout>

## 모델 관리

모델 관리 페이지는 로컬 대규모 모델의 다운로드, 활성화, 업데이트 및 제거에 사용되며, OpenAI 호환 API 액세스도 관리할 수 있습니다.

![AI Model Management](/images/ko/app-guide/settings-img/ai-model-management.png)

### 모델 카드

각 모델에는 다음이 표시됩니다:

| 필드 | 설명 |
| --- | --- |
| 모델 이름 | 예: Qwen3.5-0.8B, Qwen3-8B, Gemma4-E4B 등. |
| 유형 | Text Generation, Any-to-Any 등 모델 기능 유형. |
| 크기 | 모델 파일이 차지할 것으로 예상되는 공간. |
| 상태 | 다운로드 안 됨, 다운로드 중, 다운로드됨, 현재 사용 중 등. |
| 활성화/비활성화 | 해당 모델을 사용 가능한 모델 목록에 표시할지 제어합니다. |
| 제거/삭제 | 로컬 모델 파일을 삭제합니다. 삭제 후 필요하면 다시 다운로드할 수 있습니다. |
| 모델 구성 | 모델 관련 구성을 확인하거나 수정합니다. |

### API 액세스

**API Access**를 클릭하면 OpenAI 호환 인터페이스 액세스를 관리할 수 있습니다:

| 기능 | 설명 |
| --- | --- |
| API 주소 | 로컬 모델 또는 서비스의 액세스 주소를 표시합니다. |
| API Key | 액세스 키를 생성, 확인, 업데이트 또는 삭제합니다. |
| 호출 설명 | OpenAI API와 호환되는 서드파티 앱 또는 개발 스크립트에 사용할 수 있습니다. |

<Callout title="주의" type="warn">
  로컬 모델을 삭제하면 해당 모델의 모든 로컬 파일이 영구적으로 삭제됩니다. 현재 해당 모델을 사용 중인 경우 시스템이 다른 사용 가능한 모델 또는 OpenAI 호환 API로 전환할 수 있습니다.
</Callout>

## 저장 위치

저장 위치 페이지는 로컬 모델과 인덱스 데이터의 저장 위치를 관리하고 공간 부족 보호 기능을 제공합니다.

![AI Storage](/images/ko/app-guide/settings-img/ai-model-storage.png)

### 로컬 모델 저장소

| 필드/작업 | 설명 |
| --- | --- |
| 현재 스토리지 볼륨 | 볼륨 이름, RAID 유형 및 사용 가능한 용량을 표시합니다. |
| 저장소 변경 | 로컬 대규모 모델 파일을 다른 스토리지 볼륨으로 마이그레이션합니다. 마이그레이션 중에는 로컬 모델을 일시적으로 사용할 수 없습니다. |
| 상태 | 정상, 공간 부족, 읽기 전용, 사용 불가, 마이그레이션 중 등. |

### 인덱스 데이터 저장소

| 필드 | 설명 |
| --- | --- |
| 상태 | 인덱스 풀의 전반적인 상태. |
| 파일 인덱스 | 파일 이름, 경로 등 기본 인덱스가 차지하는 공간. |
| 텍스트 콘텐츠 | OCR 및 문서 텍스트/벡터 데이터가 차지하는 공간. |
| 이미지 콘텐츠 | 이미지 시각 벡터 데이터가 차지하는 공간. |
| 사용 가능한 공간 | 현재 인덱스 저장소의 남은 공간. |
| 공간 부족 임계값 | 보호를 실행하는 공간 임계값. 현재 예시는 10 GB 미만일 때 작업을 일시 중지합니다. |
| 저장소 변경 | 인덱스 데이터를 다른 저장 위치로 마이그레이션합니다. |

### 공간 부족 보호

활성화하면 사용 가능한 공간이 설정된 임계값보다 낮을 때 시스템이 모델 다운로드와 인덱스 재구축 작업을 자동으로 일시 중지하여 스토리지가 가득 차 서비스 이상이 발생하는 것을 방지합니다. 공간이 복구되면 작업을 수동으로 계속할 수 있습니다.

<Callout title="권장 사항" type="info">
  대규모 모델과 인덱스 데이터는 파일 수가 늘어날수록 증가합니다. 모델과 인덱스를 용량이 충분하고 상태가 정상인 SSD 스토리지 볼륨에 두고 공간 부족 보호를 켜 두는 것이 좋습니다.
</Callout>

## 기능 상태 및 처리

| 상태 | 의미 | 권장 조치 |
| --- | --- | --- |
| 정상 | 기능을 사용할 수 있습니다. | 모델을 최신 상태로 유지하고 정기적으로 인덱스를 재구축합니다. |
| 비활성화됨 | 관리자 또는 사용자가 해당 기능을 껐습니다. | 필요할 때 다시 켭니다. |
| 설치/업데이트 중 | 종속 항목과 모델을 다운로드하거나 업데이트하고 있습니다. | 네트워크와 스토리지를 사용 가능한 상태로 유지합니다. |
| 재구축 중 | 인덱스 데이터를 재구축하고 있습니다. | 완료될 때까지 기다리고 대량 파일 이동을 피합니다. |
| 마이그레이션 중 | 모델 또는 인덱스를 새 볼륨으로 이동하고 있습니다. | 로컬 모델을 일시적으로 사용할 수 없을 수 있습니다. |
| 공간 부족 일시 중지 | 남은 공간이 임계값보다 낮습니다. | 공간을 정리하거나 더 큰 볼륨으로 마이그레이션합니다. |
| 읽기 전용 | 저장 위치가 읽기 전용입니다. | 볼륨 상태를 확인하고 저장 위치를 변경합니다. |
| 이상/실패 | 종속 항목, 스토리지 또는 서비스에 이상이 있습니다. | 로그 센터를 확인하고 복구 또는 재구축을 시도합니다. |

## 인덱스 유지 관리 권장 사항

| 작업 | 적용 상황 |
| --- | --- |
| 전체 설치/업데이트 | 기능을 처음 활성화하거나 기능의 새 버전이 있을 때. |
| 복구 | 인덱스 상태가 비정상이거나 일부 파일을 검색할 수 없을 때. |
| 인덱스 재구축 | 대량 파일 이동 후 또는 인덱스 저장소 마이그레이션 후 결과가 불완전할 때. |
| 기능 비활성화 | 얼굴, OCR, 문서 의미 또는 시각 검색이 필요 없을 때. |
| 저장소 마이그레이션 | 현재 볼륨 공간이 부족하거나 더 빠른 SSD로 교체할 때. |

<Callout title="인덱스 범위" type="info">
  인덱스는 시스템이 읽을 수 있고 권한이 있는 파일에만 적용됩니다. 암호화된 파일, 아직 지원되지 않는 형식, 손상된 파일 또는 권한이 부족한 디렉터리는 인덱스 실패 통계에 나타날 수 있습니다.
</Callout>

## 모델 선택 및 유지 관리

| 항목 | 권장 사항 |
| --- | --- |
| 소형 모델 | 차지하는 공간이 작고 응답이 빨라 가벼운 질의응답과 저사양 기기에 적합합니다. |
| 대형 모델 | 이해와 생성 능력이 더 뛰어나지만 메모리/스토리지를 더 많이 사용하고 응답이 느릴 수 있습니다. |
| Any-to-Any 모델 | 다양한 입력/출력 형태가 필요한 시나리오에 적합하며 다운로드 용량이 일반적으로 더 큽니다. |
| 로컬 모델 | 데이터가 기기 외부로 나가지 않아 프라이버시 시나리오에 적합하지만 하드웨어 연산 성능의 제약을 받습니다. |
| OpenAI 호환 API | 외부 서비스에 연결할 수 있으며 Base URL, 모델 이름 및 API Key를 구성해야 합니다. |
| 모델 삭제 | 공간을 확보합니다. 나중에 다시 다운로드할 수 있지만 트래픽과 시간이 소모됩니다. |

## API Access 사용 시 주의 사항

- API Key는 필요한 자격 증명만 저장하며 코드 저장소에 제출하거나 공개적으로 공유하지 마십시오.
- 호출 주소는 신뢰할 수 있는 내부 네트워크 또는 리버스 프록시/방화벽으로 제한된 클라이언트에만 노출해야 합니다.
- Key가 유출되면 즉시 삭제하거나 업데이트하십시오.
- 외부 호출은 기기 부하, 모델 상태 및 스토리지 공간의 영향을 받습니다.

## 스토리지 마이그레이션 주의 사항

1. 마이그레이션 전에 대상 볼륨 용량이 모델과 인덱스 데이터의 합계보다 큰지 확인하고 증가할 공간을 확보하십시오.
2. 마이그레이션 중에는 모델 구성을 수정하거나 기기를 재시작하지 마십시오.
3. 로컬 모델 마이그레이션이 완료되기 전에는 채팅 기능을 일시적으로 사용하지 못할 수 있습니다.
4. 인덱스 마이그레이션 후에는 검색으로 한 번 검증하고 필요한 경우 인덱스를 재구축하십시오.

스토리지 공간 페이지는 **스토리지 공간**과 **SSD 캐시 가속**으로 나뉩니다. 스토리지 공간 탭은 하나 이상의 하드 디스크로 구성된 볼륨을 생성하고 관리하는 데 사용되며, SSD 캐시 탭은 고속 SSD를 HDD 볼륨의 캐시로 사용하여 핫 데이터 접근 성능을 높이는 데 사용됩니다.

## 스토리지 공간 탭

![Storage](/images/ko/app-guide/settings-img/storage.png)

### 스토리지 볼륨 목록

각 스토리지 볼륨 카드에는 다음이 표시됩니다:

| 필드 | 설명 |
| --- | --- |
| 이름 | 스토리지 볼륨 이름입니다. 예: Storage volume1. |
| 상태 | Normal, Degraded 등 상태이며 비정상일 때는 가능한 한 빨리 하드 디스크를 확인해야 합니다. |
| 스토리지 모드/RAID | Basic, JBOD, RAID0, RAID1, RAID5, RAID6, RAID10 등. |
| 용량 | 사용된 용량 / 전체 용량. |
| 하드 디스크 유형 | HDD, SSD 등. |
| 인터페이스 | SATA, NVMe 등. |
| 파일 시스템 | 현재 볼륨이 사용하는 파일 시스템입니다. 예: Btrfs. |
| 사용 중인 하드 디스크 | 해당 볼륨을 구성하는 하드 디스크와 용량을 표시하며 하드 디스크를 클릭하면 해당 정보를 확인할 수 있습니다. |

### 스토리지 볼륨 작업

스토리지 볼륨 카드 또는 더 보기 메뉴에서 다음 작업을 제공할 수 있습니다:

| 작업 | 설명 |
| --- | --- |
| 스토리지 공간 생성 | 사용 가능한 하드 디스크를 새 스토리지 볼륨으로 초기화합니다. 생성 과정에서 선택한 하드 디스크가 포맷됩니다. |
| 스토리지 모드 수정 | 호환 조건에서 RAID 유형을 변경하며 하드 디스크를 추가하거나 제거해야 할 수 있습니다. |
| 하드 디스크 추가 | 지원되는 RAID 볼륨의 용량을 확장하며 새 하드 디스크는 포맷됩니다. |
| 핫 스페어 추가/제거 | RAID 볼륨에 예비 하드 디스크를 지정합니다. 구성원 디스크 장애 시 핫 스페어가 자동으로 복구에 참여할 수 있습니다. |
| 하드 디스크 교체 | 장애 또는 용량 업그레이드 시나리오에서 구성원 디스크를 교체합니다. |
| 복구/검사 | 비정상 상태 문제 해결 및 복구에 사용합니다. |

### RAID 및 스토리지 모드

| 모드 | 하드 디스크 요구 사항 | 장점 | 위험/제한 |
| --- | --- | --- | --- |
| Basic | 1개 | 단일 디스크 용량을 최대한 활용합니다. | 데이터 보호가 없어 하드 디스크 손상 시 해당 디스크 데이터가 손실됩니다. |
| JBOD | 최소 1개 | 여러 하드 디스크를 하나의 사용 가능 공간으로 연결하여 확장이 간단합니다. | 이중화가 없어 구성원 디스크 하나만 고장 나도 전체 공간 데이터가 손실될 수 있습니다. |
| RAID 0 | 최소 2개 | 읽기/쓰기 속도가 가장 빠르고 용량 활용률이 높습니다. | 데이터 보호가 없어 하드 디스크 하나만 손상되어도 모든 데이터가 손실됩니다. |
| RAID 1 | 최소 2개 | 미러링 보호로 n-1개 디스크 장애까지 데이터 손실 없이 지원합니다. | 용량 활용률이 낮습니다. |
| RAID 5 | 최소 3개 | 성능과 보호를 함께 제공하며 단일 디스크 장애 후 패리티로 복구할 수 있습니다. | 쓰기가 상대적으로 느리고 복구 시간이 깁니다. |
| RAID 6 | 최소 4개 | 이중 패리티로 동시에 2개 디스크 장애를 지원합니다. | 쓰기 속도와 공간 활용률이 더 낮아집니다. |
| RAID 10 | 최소 4개이며 짝수 | 미러링 후 스트라이핑으로 고성능과 높은 보호를 함께 제공합니다. | 공간 활용률이 약 절반입니다. |

### 파일 시스템 선택

생성 마법사에서 파일 시스템을 선택할 수 있습니다:

| 파일 시스템 | 적합성 |
| --- | --- |
| Btrfs | 스냅샷, 하위 볼륨 및 효율적인 복사를 지원하여 유연한 백업과 버전 관리가 필요한 가정 사용자 또는 가벼운 개발자에게 적합합니다. |
| EXT4 | 성숙하고 안정적이며 기존 파일 서비스, 리소스가 제한된 기기 또는 안정성을 중시하는 사무 환경에 적합합니다. |

### 스토리지 공간 생성 절차

1. **스토리지 공간 생성**을 클릭합니다.
2. 사용 가능한 하드 디스크를 선택합니다. 시스템이 사용 가능한 RAID 모드와 예상 용량을 실시간으로 계산합니다.
3. 스토리지 모드/RAID를 선택하고 사용 가능한 용량, 데이터 보호 용량 등의 정보를 확인합니다.
4. 파일 시스템 형식을 선택합니다.
5. 해당 스토리지 공간을 사용할 사용자를 선택하고 일반 사용자의 용량 제한을 설정할 수 있습니다.
6. 요약과 포맷 경고를 확인합니다.
7. 생성을 시작하고 포맷이 완료될 때까지 기다립니다.

<Callout title="위험 작업" type="error">
  스토리지 볼륨을 생성, 수정, 확장 또는 교체하면 선택한 하드 디스크가 포맷되고 모든 데이터가 삭제될 수 있습니다. 작업이 시작되면 전원을 끄거나 재시작하거나 하드 디스크를 분리·삽입하지 마십시오. 반드시 중요한 데이터를 먼저 백업하십시오.
</Callout>

## SSD 캐시 가속 탭

SSD 캐시는 핫 데이터를 고속 SSD에 저장하여 HDD 읽기 대기 시간을 줄입니다. 이 기능을 사용하기 전에 기기에 사용되지 않는 SSD가 최소 하나 설치되어 있어야 합니다.

![SSD Cache](/images/ko/app-guide/settings-img/storage-ssd-cache.png)

### SSD 캐시 생성

| 구성 항목 | 설명 |
| --- | --- |
| 가속 대상 | 가속할 HDD 스토리지 볼륨을 선택합니다. |
| 캐시 SSD | 사용 가능한 SSD를 선택합니다. 사용 가능한 SSD가 없으면 먼저 설치하거나 하드 디스크를 해제해야 합니다. |
| 캐시 이름 | 기본적으로 자동 생성할 수 있으며 용도에 따라 이름을 지정할 수도 있습니다. |
| 캐시 모드 | 읽기 전용 캐시 또는 읽기-쓰기 캐시. |
| 캐시 RAID | SSD가 여러 개일 때 캐시 RAID 모드를 선택할 수 있습니다. |
| 캐시 용량 | 용량 최대화 또는 사용자 지정 용량을 선택할 수 있으며 남은 용량은 다른 볼륨에 계속 할당할 수 있습니다. |
| 위험 확인 | 캐시 생성, SSD 포맷 및 읽기-쓰기 캐시의 정전 위험을 이해했음을 확인해야 합니다. |

### 캐시 모드 비교

| 모드 | 설명 |
| --- | --- |
| 읽기 전용 캐시 | 핫 읽기 데이터만 캐시하며 SSD 장애 또는 정전 시 원본 데이터 위험이 낮습니다. |
| 읽기-쓰기 캐시 | 읽기와 쓰기를 모두 가속하여 성능이 더 좋지만 SSD 장애 또는 비정상 정전 시 아직 기록되지 않은 데이터에 영향을 줄 수 있습니다. |

### 캐시 관리

| 작업 | 설명 |
| --- | --- |
| 상태 보기 | 캐시 이름, 모드, 용량, 적중률 및 연결된 볼륨을 확인합니다. |
| 캐시 삭제 | 캐시와 볼륨의 연결을 해제합니다. 읽기-쓰기 캐시를 삭제하기 전에 시스템이 데이터 기록을 보장하며, 이 기간에는 전원을 끄거나 SSD를 제거하지 마십시오. |
| 캐시 복구 | 캐시가 저하되거나 손상된 경우 안내에 따라 모든 캐시 디스크를 다시 연결하고 복구를 시도할 수 있습니다. |
| 기존 캐시 할당 | 기존 캐시 풀의 남은 용량을 사용하여 다른 볼륨을 가속합니다. |

<Callout title="데이터 안전" type="warn">
  SSD 캐시를 생성하면 선택한 SSD의 데이터가 지워집니다. 읽기-쓰기 캐시는 안정적인 전원 공급이 필요하며 비정상 정전 또는 SSD 장애는 데이터 위험을 초래할 수 있습니다. SSD를 제거하기 전에 반드시 시스템에서 해당 캐시를 먼저 삭제하십시오.
</Callout>

## 스토리지 상태 해석

| 상태/표시 | 의미 | 권장 처리 |
| --- | --- | --- |
| Normal | 스토리지 볼륨을 정상적으로 읽고 쓸 수 있습니다. | 일상적인 백업과 하드 디스크 상태 검사를 유지하십시오. |
| Degraded | RAID 이중화가 저하되었지만 일반적으로 데이터에 계속 접근할 수 있습니다. | 즉시 데이터를 백업하고 구성원 디스크를 확인하며 가능한 한 빨리 복구하거나 하드 디스크를 교체하십시오. |
| Damaged/이상 | 스토리지 구조 또는 구성원 디스크에 심각한 이상이 있습니다. | 쓰기를 계속하지 말고 읽을 수 있는 데이터를 먼저 백업한 후 지원에 문의하십시오. |
| Syncing/복구 중 | RAID가 동기화 또는 재구축 중입니다. | 전원 공급을 안정적으로 유지하고 재시작, 전원 차단 또는 하드 디스크 분리·삽입을 하지 마십시오. |
| Formatting | 포맷 중입니다. | 완료될 때까지 기다리고 작업을 중단하지 마십시오. |
| Read-only | 시스템이 연결, 하드 디스크 또는 파일 시스템 위험을 감지하여 보호를 위해 쓰기를 금지했습니다. | 하드 디스크와 연결을 확인하고 데이터를 백업한 후 안내에 따라 복구하십시오. |
| 핫 스페어 | 하드 디스크가 대기 상태이며 구성원 디스크 장애 시 자동으로 복구에 참여할 수 있습니다. | 핫 스페어 디스크를 정상 상태로 유지하고 임의로 다른 용도로 사용하지 마십시오. |

## 생성 또는 수정 전 체크리스트

1. 선택한 하드 디스크에 보존해야 할 데이터가 없는지 확인합니다.
2. 하드 디스크 상태, 온도, 전원 인가 시간 및 S.M.A.R.T 결과를 확인합니다.
3. 하드 디스크 수, 인터페이스 및 용량이 대상 RAID 요구 사항을 충족하는지 확인합니다.
4. 예상 사용 가능 용량, 데이터 보호 용량 및 미사용 용량을 이해합니다.
5. 백업, 다운로드, 동기화, 컨테이너, 인덱싱 및 데이터베이스 쓰기 작업을 중지합니다.
6. 무정전 전원을 준비하거나 전력이 불안정한 시간대를 피합니다.
7. 현재 스토리지 볼륨 이름, 구성원 디스크 번호 및 마운트 경로를 기록합니다.

## RAID 선택 권장 사항

| 요구 사항 | 권장 모드 |
| --- | --- |
| 단일 디스크 최대 용량, 이중화는 고려하지 않음 | Basic |
| 여러 디스크를 순차 연결하고 이후 계속 추가 | JBOD |
| 임시 캐시, 재구축 가능한 데이터, 속도 추구 | RAID 0 |
| 두 디스크로 중요한 사진과 문서 보호 | RAID 1 |
| 가정 또는 소규모 팀에서 용량, 성능, 보호의 균형 | RAID 5 |
| 더 높은 장애 허용도, 충분한 하드 디스크 수 | RAID 6 |
| 고성능과 미러링 보호 필요 | RAID 10 |

<Callout title="용량 안내" type="info">
  RAID 사용 가능 용량은 패리티, 미러링 및 하드 디스크 용량 차이의 영향을 받습니다. 용량이 다른 하드 디스크로 RAID를 구성할 때는 일반적으로 더 작은 용량 또는 모드 규칙에 따라 계산됩니다. 생성 마법사의 예상 용량이 최종 판단 기준입니다.
</Callout>

## 핫 스페어 정책

- **전역 핫 스페어/풀 내 핫 스페어**: 연결된 스토리지 공간의 구성원 디스크 장애 시 자동으로 대체하여 복구 시간을 단축합니다.
- **적용 시나리오**: 하드 디스크를 즉시 교체하기 어려운 원격 배포, 중요한 업무 볼륨, 하드 디스크 수가 많은 RAID 6/10.
- **주의 사항**: 핫 스페어는 백업이 아닙니다. 동기화 중에는 성능이 저하될 수 있으며 원래 볼륨은 복구가 완료될 때까지 저하 상태로 유지됩니다.

## SSD 캐시 선택 권장 사항

| 시나리오 | 권장 사항 |
| --- | --- |
| 주로 반복 읽기 핫 데이터 향상 | 읽기 전용 캐시, 위험이 낮습니다. |
| 쓰기 응답 향상이 필요하고 UPS가 있음 | 읽기-쓰기 캐시를 검토할 수 있습니다. |
| UPS가 없거나 데이터가 매우 중요함 | 읽기-쓰기 캐시를 피하고 HDD/RAID 성능 향상을 우선하십시오. |
| 여러 사용자가 동일 디렉터리에 동시 접근 | 읽기 전용 캐시의 효과가 비교적 뚜렷합니다. |
| 작은 파일을 대량으로 무작위 쓰기 | 앱 쓰기 패턴과 SSD 수명을 함께 평가해야 합니다. |

읽기-쓰기 캐시를 생성하거나 삭제할 때 시스템은 SSD에 아직 기록되지 않은 데이터를 HDD에 동기화해야 할 수 있습니다. 이 기간에는 전원을 끄거나 재시작하거나 SSD를 제거하지 마십시오.

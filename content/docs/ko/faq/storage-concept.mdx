StationOS Pro에서 **하드 디스크**와 **스토리지 공간**은 데이터 스토리지를 구성하는 두 가지 핵심 개념입니다. 간단히 말해, 하드 디스크는 데이터의 물리적 매체이고, 스토리지 공간은 파일을 실제로 저장하고 관리하는 논리 영역입니다. 두 가지의 관계를 이해하는 것은 용량을 합리적으로 계획하고, 데이터 안전을 보장하며, 장치 성능을 최대한 발휘하기 위한 기초가 됩니다.

## 하드 디스크: 데이터의 물리적 매체

하드 디스크는 데이터를 실제로 저장하는 물리 장치입니다. StationPC 장치는 기계식 하드 디스크(HDD)와 반도체 디스크(SSD)를 모두 지원합니다:

- **HDD(기계식 하드 디스크)**: 용량이 크고 단위 용량당 가격이 낮아 사진, 동영상, 다운로드 자료 등 대용량 데이터의 장기 저장에 적합합니다.
- **SSD(반도체 디스크)**: 읽기/쓰기 속도가 빨라 Docker 컨테이너, 가상 머신 등 높은 성능이 요구되는 시나리오에 적합하며, HDD 스토리지 공간의 캐시 가속으로도 사용할 수 있습니다.

하드 디스크 모델과 용량 선택은 [HDD 호환성 목록](../compatible/support-hdd)을 참고하세요.

## 스토리지 공간: 데이터를 실제로 사용하는 논리 영역

스토리지 공간은 사용자가 데이터를 실제로 저장하고 관리하는 논리 영역으로, 하나의 독립적인 "가상 하드 디스크"에 해당합니다. 시스템은 RAID 기술로 한 개 이상의 하드 디스크를 스토리지 공간으로 구성하지만, 화면에서는 한 번의 조작만으로 충분합니다: **스토리지 공간을 직접 생성**하면 되며, 스토리지 풀을 별도로 만들 필요가 없습니다.

스토리지 공간 생성 시 마법사가 다음 선택을 안내합니다:

1. **하드 디스크 선택**: 내장 하드 디스크 또는 외장 스토리지에서 구성에 참여할 하드 디스크를 선택합니다.
2. **스토리지 모드 선택**: 즉 RAID 모드로, 용량 활용 방식과 데이터 보호 수준을 결정합니다.
3. **파일 시스템 선택**: Btrfs 또는 EXT4.
4. **사용 권한 설정**: 해당 스토리지 공간을 사용할 사용자를 선택하고, 일반 사용자의 사용 가능 용량을 제한할 수도 있습니다.
5. **확인 및 생성**: 요약과 포맷 경고를 확인한 후 생성을 시작합니다.

생성이 완료되면 스토리지 공간 카드에 상태, 스토리지 모드, 사용 중인 용량, 파일 시스템, 멤버 디스크, 핫 스페어 등의 정보가 표시되어 스토리지 상태를 언제든 파악할 수 있습니다.

## 스토리지 모드: 용량과 안전의 균형점

스토리지 모드(RAID)는 여러 하드 디스크가 어떻게 협력하여 작동하는지 결정합니다. 모드마다 용량 활용률과 데이터 안전에 대한 중점이 다릅니다:

- **Basic**: 단일 디스크를 독립적으로 사용. 용량 활용률이 가장 높지만 데이터 보호가 없습니다.
- **JBOD**(화면에는 Linear로 표시): 여러 하드 디스크의 용량을 선형으로 연결하여 하나의 공간으로 만듭니다. 확장은 간단하지만 중복성이 없습니다.
- **RAID 0**: 데이터를 여러 하드 디스크에 분산하여 저장합니다. 읽기/쓰기 속도가 빠르지만, 하나의 하드 디스크라도 손상되면 모든 데이터가 손실됩니다.
- **RAID 1**: 데이터를 멤버 디스크 간에 미러링하여 저장합니다. 일부 하드 디스크에 장애가 발생해도 데이터를 잃지 않습니다.
- **RAID 5 / RAID 6**: 패리티를 통해 내결함성을 제공하며 용량 활용률과 안전을 모두 고려합니다. 베이 수가 많은 장치에 적합합니다.
- **RAID 10**: 먼저 미러링한 후 스트라이핑합니다. 높은 성능과 높은 보호를 모두 갖추며, 공간 활용률은 전체 용량의 약 절반입니다.

각 모드의 하드 디스크 수 요구 사항, 용량 계산 방식, 자세한 비교는 [스토리지 공간 설정](../app-guide/settings/storage)을 참고하세요.

또한 RAID 스토리지 공간에 **핫 스페어**를 지정할 수 있습니다: 멤버 디스크에 장애가 발생하면 핫 스페어가 자동으로 교체되어 재구축에 참여하여, 데이터가 저하 상태에 있는 시간을 줄여줍니다.

## 하드 디스크와 스토리지 공간 관계 요약

한 문장으로 요약하면: **하드 디스크는 물리적 용량을 제공하고, 스토리지 모드는 구성 방식을 결정하며, 스토리지 공간은 최종적으로 제공되는 사용 가능 영역입니다.**

- **하드 디스크 → 스토리지 공간**: 스토리지 공간 생성 시 선택한 하드 디스크가 스토리지 모드에 따라 하나의 전체로 구성됩니다. 모드가 실제 사용 가능 용량과 내결함성을 결정합니다.
- **스토리지 공간 → 사용자 데이터**: 스토리지 공간에서 공유 폴더를 만들고, 파일을 업로드하고, 접근 권한을 설정한 후에는 [파일 관리자](../app-guide/files) 앱 또는 SMB, WebDAV 등의 프로토콜을 통해 다양한 장치에서 데이터에 접근할 수 있습니다.

## 다른 NAS 시스템과의 차이: "스토리지 풀"이 없는 이유는?

많은 NAS 시스템은 "하드 디스크 → 스토리지 풀 → 스토리지 공간"의 3계층 구조를 채택합니다: 먼저 하드 디스크를 스토리지 풀로 묶고, 그 풀 위에 여러 스토리지 공간을 나눕니다.

StationOS Pro는 이 두 단계를 한 단계로 통합했습니다: 스토리지 공간 생성 시 하드 디스크와 스토리지 모드만 선택하면 시스템이 하위 계층의 풀링을 자동으로 완료합니다. 이러한 선택의 결과는 다음과 같습니다:

- **장점**: 절차가 더 간단하고 직관적입니다. "스토리지 풀" 개념을 먼저 이해하지 않아도 스토리지를 올바르게 구성할 수 있습니다.
- **한계**: 하나의 하드 디스크 그룹은 하나의 스토리지 공간에만 대응되며, 같은 그룹에서 여러 공간을 다시 나눌 수 없습니다. 서로 독립적인 여러 공간이 필요하다면 다른 하드 디스크로 각각 생성하세요.

## 스토리지 계획 조언

| 필요 | 조언 |
| --- | --- |
| 사진, 문서 등 중요 데이터 | RAID 1 이상의 중복 모드 사용 및 정기 백업 유지 |
| Docker, 가상 머신 등 고성능 시나리오 | SSD로 스토리지 공간 구성 또는 SSD 캐시 가속 활성화 |
| 동영상, 다운로드 등 대용량 데이터 | 대용량 HDD와 JBOD 또는 RAID 5 조합 |
| 다수 인원 협업 | 스토리지 공간을 나누어 생성하거나 폴더 권한으로 멤버별 데이터 분리 |

<Callout title="안내" type="idea">
RAID가 제공하는 것은 하드 디스크 장애에 대한 내결함성이며 백업을 대체할 수 없습니다. 중요한 데이터는 계속 "3-2-1" 백업 원칙을 따르는 것이 좋습니다: 최소 3개의 데이터 사본을 유지하고, 2종류의 매체에 보관하며, 그중 1개는 다른 장소에 보관합니다.
</Callout>

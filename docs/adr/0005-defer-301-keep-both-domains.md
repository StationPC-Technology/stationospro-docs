# 0005 — 旧站两域名长期保留，301 延后

日期：2026-11
状态：已采纳

## 背景

常规做法是合并完成后立刻把老域名 301 到新站。但旧站的两个域名有**线下分发**：

- `help.stationpc.cn`、`help.stationpc.com` 印在包装盒与说明书上（二维码），实物已流入市场，无法回收。
- 两个域名服务的是**同一份构建产物**（`.cn` 是中文站、`.com` 是英文站，路径前缀相同）。
- 新站是 Node 服务端部署（依赖 `/api/search`、动态 OG、语言中间件），不能纯静态托管；旧站是 nginx 静态镜像。

## 决策

1. **两个域名都长期保留**，不设下线日期。
2. **301 延后**：先让旧站与新站并存，旧站加 `<meta name="robots" content="noindex,follow">` + `<link rel="canonical" href="https://docs.stationpc.com/…">`，并在旧站顶栏加公告条链到新站对应产品落地页。
3. **触发 301 的四条验收**：8 语言齐 / 站内死链 0 / 图片全通 / 侧栏无孤儿。全部满足后，再把 301 作为**独立变更**提（映射表见 `merge-plan.md` 附录 B）。
4. GA 双跑：旧站 GA（`G-KN8GW9JM3K` 中文 / `G-DS9C35LTB6` 英文）与新站 PostHog 并行 2 周，再决定归因口径。

## 后果

- 包装盒上的二维码不会 404，用户从线下进来仍能查到文档（旧站内容冻结但可读）。
- 重复内容的风险由 `noindex` + canonical 兜住；旧站不再参与搜索排名。
- 双站并存期间，任何旧站内容修正都要在新站同步（旧站已冻结，故实际是：旧站只修**严重错误**，其余以新站为准）。
- 运维多一套静态镜像，成本可忽略（已有 Dockerfile）。

## 被否决的方案

1. **立即 301**：包装盒二维码会在用户手里失效；且新站上线初期若出现 404 或语言缺失，用户没有退路。否决。
2. **旧站完全下线**：同 1，且丢掉过渡期回退能力。否决。
3. **保留旧站作为唯一入口、新站只做内部预览**：等于不合并，成本白付。否决。

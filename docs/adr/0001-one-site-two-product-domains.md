# 0001 — 一个站点、两个产品域

日期：2026-11
状态：已采纳

## 背景

`stationpc_nas_help`（PocketCloud，便携式 NAS）与 `stationospro-docs`（StationOS Pro，桌面式 NAS）要合并。最初的想法是把前者整并进后者的现有结构里。

调研后事实是：两站**不是同一产品的两版文档**。

| | PocketCloud | StationOS Pro |
|---|---|---|
| 固件 | v3.2.1.11（独立版本线） | 独立版本线 |
| 客户端 | StationCloud | StationNAS / StationHub |
| 硬件 | PA100 / PA100 Pro / PA200（Dock 是底座配件） | DA400 / DA400 Air（Air 为低配） |
| 内容量 | 中文 125 篇 | 中文 43 篇 |
| 功能重合 | 文件协议、Docker、备份、相册、影视、兼容列表——**概念同名但操作路径不同** | 同左 |

同一篇「如何用 WebDAV 挂载」在两个产品上的菜单路径、截图、限制都不一样。若按功能合并成一棵树（`/docs/file-service/webdav` 下用 Tabs 切产品），每篇都要维护两套正文 + 两套截图，写作成本翻倍，且搜索会混出错误答案。

## 决策

**一个站点、两个并列的产品域、一层薄共享外壳**：

```
/desktop/**          产品域 A（桌面式 · StationOS Pro）
/portable/**         产品域 B（便携式 · StationOS）
/                     总览（产品选择）
/policies/*           法务（两产品共用）
/contact              联系我们
```

产品段按**产品线**命名而非产品名，理由与改名/新型号的关系见 [0007](./0007-line-based-url-slugs.md)。产品域之间不互相嵌套、不共用目录；共享的只有法务、联系、全站搜索与站点外壳。

## 后果

- 好处：PocketCloud 的 17 组结构可 100% 平移，URL 只多一层产品段（域名已含 `docs`，不再重复前缀）；写作时只需关心一个产品；搜索可按产品域过滤，答案不串味。
- 代价：两产品确实重复的概念（"怎么备份"）会出现两篇内容，靠交叉链接而非复用解决；未来若出第三个产品线，再复制一个域即可，模型可扩展。
- 约束：导航必须提供产品切换（顶栏两个按钮），否则用户会困在某一域里——这是顶栏存在的**唯一硬理由**。

## 被否决的方案

1. **按功能合并成一棵树**（`/file-service/` 下用 Tabs 分产品）：标题短、SEO 集中，但每篇要写双份正文，且现有 0 篇用 Tabs 的先例，等于把"移植"变成"重写"。否决。
2. **两站继续并存、只做交叉链接**：维护两套技术栈、两套 CI、两套翻译流水线，正是本次要消除的成本。否决。
3. **子域**（`pocketcloud.docs.stationpc.com`）：SEO 分成两个站点，共享外壳（搜索、语言切换）要跨域实现。否决。
